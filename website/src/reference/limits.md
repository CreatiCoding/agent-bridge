# 한도와 시간

이 페이지는 사용자가 겪는 시간 한도, 주기, 개수·크기 한도를 빠짐없이 정리해요. 숫자 때문에 생기는 증상과 대처는 [문제 해결](/guide/operate/troubleshooting)을, 세션을 다루는 방법은 [폰에서 세션 다루기](/guide/use/sessions)를 보세요.

이 페이지는 SPEC 판 1.309 기준이에요.

시간은 ms(밀리초) 단위로 적고, 알아보기 쉽게 괄호에 풀어 써요.

## 서버 → 맥 명령 대기

서버는 연동 페이지를 거쳐 에이전트에 명령을 보내고 답을 기다려요. 시간 안에 답이 없으면 그 요청은 실패하고 호스트 로그에 `error` 한 줄이 남아요.

| 대상 | 한도 | 넘으면 |
|---|---|---|
| 연동 페이지의 받음 확인 | 12,000 ms (12초) | "그 맥의 연동 탭이 명령을 받지 못했습니다 …" |
| 연결 안 된 맥에 보낸 명령 | 즉시 | "호스트가 연결돼 있지 않습니다" |
| 일반 명령(폴더 목록, 화면, `AGENTS.md`, 잠자기, 헤드리스 연동 모드, 압축 시점) | 15,000 ms (15초) | "에이전트가 명령을 받았지만 제때 답하지 않았습니다" |
| 스킬 메뉴 | 20,000 ms (20초) | 같음 |
| 맥의 대화 목록, 버리기 정보, 지금 복구, 그림·기록 받기 | 30,000 ms (30초) | 같음 |
| 새 세션, 복제, 버리기 | 60,000 ms (1분) | 같음 |
| 가져오기, 옮기기 전 내보내기(flush) | 90,000 ms (1분 30초) | 같음 |
| 대화 기록 정리, 옮기는 대화 넘기기(한 쪽) | 120,000 ms (2분) | 같음 |
| 옆길 질문(btw) | 150,000 ms (2분 30초) | 같음 |
| 가벼운 복제 | 240,000 ms (4분) | 같음 |
| 다시 열기·옮기기(open) | 600,000 ms (10분) | 같음 |

## 연결과 주기

| 항목 | 값 | 설명 |
|---|---|---|
| 에이전트 상태 보고 | 15,000 ms (15초) 마다 | 연동 페이지가 붙어 있는 동안 보내요. |
| 서버의 맥 확인(ping) | 15,000 ms (15초) 마다 | 왕복 시간(`rtt`)을 재요. |
| 응답 없음 판정 | 50,000 ms (50초) | 마지막 상태 보고 뒤 이만큼 조용하면 "응답 없음"이에요. 판정은 15초마다라서 늦어도 65초 안에 보여요. |
| 연결 끊김 띠 | 8,000 ms (8초) | 조작 페이지가 서버와 이만큼 끊기면 띠를 보여요. 끊긴 동안 2,000 ms 마다 다시 그려요. |
| 조작 페이지 스트림 다시 붙기 | 2,000 ms (2초) 뒤 | 스트림이 닫히면 이만큼 뒤에 다시 붙어요. |
| 서버 스트림 유지 신호 | 20,000 ms (20초) 마다 | |
| 에이전트 스트림 유지 신호 | 5,000 ms (5초) 마다 | 20,000 ms 동안 조용하면 연동 페이지가 다시 연결해요. |
| 연동 페이지 → 서버 다시 보내기 | 2,000 ms (2초) 뒤 | 올리기에 실패하면 순서를 지켜 횟수 제한 없이 다시 보내요. |
| 연동 페이지 → 에이전트 명령 전달 | `open` 120,000 ms, 그 밖 10,000 ms | |
| 기기 화면 새로 읽기 | 10,000 ms (10초) 마다 | |
| 보고 있는 세션 알리기 | 30,000 ms (30초) 마다 | 서버는 45,000 ms 동안 "보는 중"으로 쳐요. 그동안은 웹 푸시를 보내지 않아요. |
| 상대 시각("방금", "N분 전") 다시 그리기 | 30,000 ms (30초) 마다 | 45초 전까지는 "방금"이에요. |
| 점검 다시 돌리기 | 문제가 있으면 60,000 ms (1분), 없으면 600,000 ms (10분) | [점검 항목](/reference/checks#점검이-도는-때)을 보세요. |
| 자동 복구 | 60,000 ms (1분) 마다 | |
| 모델 목록 확인 | 21,600,000 ms (6시간) 마다 | 10분마다 보는 타이머가, 마지막 확인이 6시간을 넘었고 연결된 맥이 있을 때만 물어요. |
| 통계 다시 계산 | 30,000 ms (30초) | 통계는 최대 30초 늦을 수 있어요. |

## 세션 동작

| 항목 | 값 | 설명 |
|---|---|---|
| 전달 확인 | 5,000 ms (5초) | 글을 붙여 넣고 Enter 를 보낸 뒤 이만큼 지나 턴이 시작됐는지 확인해요. 안 됐으면 한 번 더 넣고, 그래도 안 되면 알려요. |
| 턴 닫기(훅을 놓쳤을 때) | 15,000 ms (15초) | 빈 입력칸이 보이고 이만큼 조용하면 턴이 끝났다고 봐요. |
| 확인 창 답의 포커스 기다림 | 60,000 ms (1분) | |
| 같은 확인 창 되풀이 판정 | 900,000 ms (15분) | 이 안에 세 번째 뜨면 다시 묻지 않고 설명해요. |
| "아직 뜨는 중" 알림 | 90,000 ms (90초) | 시작 뒤 이만큼 지나도 뜨는 중이면 한 번 알려요. |
| 맥 대화 목록의 "활성" | 60,000 ms (1분) | 대화 파일이 이 안에 바뀌었으면 활성이에요. |
| 되살리기 | 마지막으로 살아 있던 때가 43,200,000 ms (12시간) 안인 세션, 최대 5개 | 맥이 다시 켜지면 가장 최근 것부터 다시 열어요. 6번째부터는 글을 보낼 때 다시 열려요. |
| 훅이 오지 않는 세션 | 띄운 지 120,000 ms (2분) | 이만큼 지나도 훅을 한 번도 못 받으면 기기 화면에 경고가 떠요. |
| 헤드리스 브라우저 다시 띄우기 | 5,000 → 10,000 → 20,000 → 40,000 → 60,000 ms | 스스로 끝나면 이 간격으로 다시 띄워요. 켜기나 지금 복구가 처음으로 되돌려요. |
| 헤드리스 브라우저 로그인 안내 | 90,000 ms (90초) | 띄운 뒤 이만큼 연동하지 않으면 다시 켜라는 안내가 떠요. |
| 헤드리스 브라우저 끝내기 | 5,000 ms (5초) | SIGTERM 뒤 이만큼 안 끝나면 강제로 끝내요. |
| 관리자 비밀번호 보관 | 300,000 ms (5분) | 맥의 메모리에만 둬요. |
| 큰 대화 입력 막기 | 대화 기록 104,857,600 byte (100MB) | 넘으면 `/` 로 시작하지 않는 글은 막아요. "대화 기록 정리"나 가벼운 복제를 쓰세요. |
| 첫 지시를 명령줄에 싣는 한도 | 8,000 byte | 넘으면 붙잡은 글로 뒀다가 Claude Code 가 뜬 뒤 넣어요. |

## 알림

| 항목 | 값 | 설명 |
|---|---|---|
| 답하지 않은 카드 다시 알리기 | 300,000 ms (5분) | 열린 뒤 한 번 다시 알려요. |
| 권한 요청 한 번 더 | 600,000 ms (10분) | 권한 요청 카드만 한 번 더 알려요. |
| 알림 보관 | 새것부터 30개, 30일 | 제목은 80자, 내용은 200자에서 잘라요. |
| 웹 푸시 구독 | 사용자마다 20개 | 넘으면 오래된 것부터 버려요. |
| 웹 푸시 유효 시간 | `TTL: 3600` (1시간) | |

| 그룹 이름 | 40자 | 잘라요. |
| 세션 제목 | 80자 | 잘라요. |
| 맥 이름 | 60자 | 잘라요. |
| 기본 프롬프트 | 8,000자 | 잘라요. |
| 첫 지시, 보내는 글 | 100,000자 | 잘라요. |

## 로그인과 잠금

| 항목 | 값 | 설명 |
|---|---|---|
| 로그인 유지 | 30일 | 고정 만료예요. 쓰는 동안 늘어나지 않아요. |
| QR 로그인 코드 | 300,000 ms (5분), 한 번만 | 헤드리스 연동 모드 켜기의 로그인 코드도 같아요. |
| 잠금 비밀번호 늘리기 | PBKDF2-SHA256 120,000회 | PBKDF2 는 Password-Based Key Derivation Function 2 예요. |
| 잠금 열쇠 | 43,200,000 ms (12시간) | 서버를 다시 띄우면 모든 열쇠가 무효예요. |
| 잠금 시도 | 60,000 ms 안에 주소마다 10번, 세션마다 10번 | 넘으면 429 예요. |
| 로그인 시도 | 60,000 ms 안에 주소마다 20번 | 넘으면 429 예요. |
| 에이전트 이전 키 | 15분 | 키를 바꾼 뒤에도 이만큼은 이전 키가 통해요. |

## 공개 데모

`BRIDGE_DEMO=1` 로 켠 공개 데모 계정에만 걸리는 한도예요.

| 항목 | 한도 |
|---|---|
| 한 주소가 여는 데모 | 3,600,000 ms (1시간) 에 10개 |
| 동시에 두는 데모 | 50개(다 차면 900,000 ms 넘게 안 쓴 가장 오래된 것을 비워요) |
| 안 쓴 데모 지우기 | 마지막 요청 뒤 86,400,000 ms (24시간) |
| 데모의 세션 수 | 20개 |
| 데모 보내기 빈도 | 60,000 ms 에 20번 |
| 데모 글 길이 | 2,000자 |
