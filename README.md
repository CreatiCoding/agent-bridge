# claude-bridge

맥에서 도는 진짜 Claude Code 세션을 웹에 잇는다. 세션을 맥북에서 아이맥으로 옮겨 이어서 작업하고, 핸드폰에서는 웹으로 어느 맥의 세션이든 대화하고 작업한다.

원칙과 기능은 [docs/PRD.md](docs/PRD.md) 에 있다. 지금은 프로토타입이다.

## 구조

```
[핸드폰·다른 기기]                       [아이맥 / 맥북]
 조작 페이지  ⇄  웹 서버  ⇄  연동 페이지(브라우저 JS)  ⇄  로컬 에이전트  ⇄  claude (zeropty·tmux)
```

- `server/` 웹 서버. GitHub 로그인, 호스트 등록, 중계, 세션 사본(트랜스크립트·작업 폴더 상태)의 디스크 보관. Claude 를 실행하지 않는다.
- `agent/` 맥에서 도는 로컬 에이전트. `127.0.0.1` 에서만 듣고 바깥으로 연결하지 않는다. `agent.mjs`(세션, 훅, 싱크), `dialog.mjs`(터미널 확인 창 읽기와 누르기), `preview.mjs`(쓰는 중인 글), `screen.mjs`(화면 판독), `mux.mjs`(세션 터미널 프로그램: zeropty 받기·확인, zeropty·tmux 고르기).
- `agent/plugins.mjs`·`agent/skills.mjs` 세션이 쓰는 플러그인 버전, 스킬 목록과 호출 수.
- `web/relay.js` 중계. 맥의 브라우저에 떠 있는 이 사이트의 페이지가 에이전트와 서버를 잇는다. 조작 페이지는 뒤에서, 연동 페이지(`web/bridge.*`)는 상태를 보여 주면서 돌린다. 사이트의 탭을 모두 닫으면 끊긴다.
- `ui/` 조작 페이지(`/`). React 로 쓰고 Vite 로 빌드한다(`ui/dist`). 서버의 bridge API(`/api/classic/stream`, `/api/sessions/…`)에 바로 붙는다. 맥에서 열면 이 페이지가 뒤에서 중계도 한다(`web/relay.js`).
- `server/cs.mjs` Slack 플러그인이 쓰는 세션 행·이벤트·Slack 블록 카드를 만든다.

서버와 에이전트 모두 의존성이 없다(node 내장 모듈만). 빌드 단계가 있는 것은 조작 페이지(`ui/`)뿐이고, 공개 npm 패키지(react, vite, typescript)만 쓴다.

세션을 붙이고 읽고 조작하는 방식은 예전 Slack 기반 도구에서 가져왔다. 무엇을 왜 가져왔는지는 [docs/LESSONS.md](docs/LESSONS.md) 에 있다.

## 쓰기

처음이라면 `https://<사이트>/guide` 를 연다. 로그인 전에는 소개와 단계 요약이, 로그인 뒤에는 단계별 시작 가이드(`/guide`)가 열리고, 맥 연결·첫 세션·Slack 연결처럼 서버가 아는 단계는 저절로 체크된다. 이 주소를 그대로 남에게 건네면 된다.

1. 사이트에 GitHub 로 로그인한다(허용된 계정만).
2. 맥에서 설치 스크립트를 **한 번** 실행한다.

   ```sh
   curl -fsSL https://<사이트>/install.sh | bash
   ```

   - `node`(18 이상)·`git`·`claude` 가 있는지 확인하고, 없는 것은 Homebrew 로 설치할지 묻는다. `tmux` 도 묻지만 없어도 된다(아래 zeropty 가 안 될 때의 대비).
   - **세션 터미널은 zeropty 다.** 에이전트는 켜질 때 [zeropty](https://github.com/CreatiCoding/zeropty) 를 GitHub 릴리스에서 받아, 에이전트 코드에 고정된 버전(0.1.3)과 SHA-256 이 맞을 때만 `~/.claude-bridge/zeropty/0.1.3/` 에 푼다(맞지 않으면 설치하지 않고 tmux 를 쓴다). 그 뒤 새로 여는 세션부터 zeropty 에서 돌고, 이미 tmux 에서 돌던 세션은 닫거나 다시 열 때까지 tmux 에 남는다. zeropty 는 처음 세션을 띄울 때 `claude` 의 서명을 바꾼 사본을 `~/.zeropty/tty/` 에 만든다(claude 한 벌 크기, 약 260MB. claude 가 업데이트되면 다시 만든다). zeropty 서버의 소켓은 `~/.zeropty/mux.sock`. tmux 로 되돌리려면 `node ~/.claude-bridge/agent.mjs service install --mux tmux`(서비스를 다시 설치하며 `agent.json` 에 `"mux": "tmux"` 를 남긴다. 떠 있는 세션은 그대로). `--mux auto` 로 같은 명령을 다시 하면 되돌림을 푼다.
   - 이 기기가 무엇인지(아이맥·맥북·맥미니·맥 스튜디오·기타)와 사이트에 보일 이름을 묻는다(`… | bash -s -- --kind imac --name "내 아이맥"` 으로 미리 줄 수 있다).
   - 에이전트를 **백그라운드 서비스**(launchd)로 설치한다. 로그인하면 자동으로 켜지고, 죽으면 다시 뜬다. 화면에는 아무것도 뜨지 않으며 터미널은 닫아도 된다.
   - 연동 페이지를 브라우저에 연다.

   그 뒤로는 **맥의 브라우저에 이 사이트를 열어 두기만 하면 된다.** 조작 화면이든 연동 페이지(`https://<사이트>/bridge`)든, 탭이 하나라도 열려 있으면 그 탭이 뒤에서 에이전트와 서버를 잇는다. 에이전트는 `127.0.0.1` 에서만 듣고 혼자서는 바깥과 통신하지 않으므로, 탭을 모두 닫으면 끊긴다.

   - Chrome 이 "로컬 네트워크의 기기에 연결" 을 허용할지 물으면 허용한다. Safari 는 이 연결을 막을 수 있어 Chrome 을 권한다.
   - 중계는 에이전트마다 탭 하나만 한다. 그 탭을 닫으면 열려 있는 다른 탭이 이어받는다.
   - 서비스 상태·제거: `node ~/.claude-bridge/agent.mjs service status`, `… service uninstall`. 다른 브라우저에서 처음 연동할 때는 `… link` 가 연결 정보가 든 링크를 연다.
   - 설치는 한 번이면 된다. 서버가 새 버전을 내주면 연동 탭이 그 파일을 에이전트에 건네고, 에이전트는 세션이 쉴 때 스스로 바꾸고 다시 시작한다(세션은 zeropty·tmux 에 남는다). 끄려면 `--no-auto-update`(다시 켜려면 `--auto-update`). 이 선택은 `agent.json` 에 남아 백그라운드 서비스에도 적용된다.
   - 에이전트가 띄우는 세션은 Claude in Chrome(`claude --chrome`)을 켠 채로 뜬다. 그 맥의 Chrome(로그인된 사이트 포함)을 세션이 쓸 수 있다. 끄려면 `--no-chrome`(다시 켜려면 `--chrome`), `agent.json` 의 `chrome` 에 남는다. 세션 하나만 끄려면 새 세션 화면의 "Claude in Chrome" 스위치를 끈다. 이미 떠 있는 세션은 새로고침해야 바뀐다.
   - 서비스 없이 터미널에서만 돌리려면 `… | bash -s -- --foreground`.
3. 폰이나 다른 기기에서 사이트를 열어 세션을 시작하고 조작한다.

## 음성 입력

세션 입력창의 마이크 버튼을 누르면 **음성 모드**가 켜진다. 입력창 대신 큰 판이 뜨고 마이크가 계속 듣는다. 말을 멈출 때마다(0.7초) 세션이 있는 맥이 그 마디를 받아써 판에 쌓고, **전송**을 누르면 모인 글이 한 메시지로 간다(계속 듣는다). **리셋**은 모인 글을 버린다. 녹음은 그 맥으로만 가고(기본), 받아쓴 글은 보통 메시지와 같은 길로 전달된다.

1. 설정 → **음성** 에서 "음성 입력" 을 켠다.
2. 세션이 도는 맥에 받아쓰기 도구를 둔다(맥마다 한 번). 없이 누르면 아래 명령을 담은 오류가 뜬다.

   ```sh
   brew install whisper-cpp                       # whisper-server, whisper-cli
   mkdir -p ~/.claude-bridge/whisper
   curl -L -o ~/.claude-bridge/whisper/ggml-large-v3-turbo-q5_0.bin \
     https://huggingface.co/ggerganov/whisper.cpp/resolve/main/ggml-large-v3-turbo-q5_0.bin   # 574 MB
   ```

   - 잡음 줄이기를 RNNoise 로 하려면(없으면 내장 스펙트럼 게이트로 한다): `brew install ffmpeg` 그리고
     `curl -L -o ~/.claude-bridge/whisper/rnnoise.rnnn https://raw.githubusercontent.com/GregorR/rnnoise-models/master/somnolent-hogwash-2018-09-01/sh.rnnn`
   - 다른 모델(`large-v3-turbo`·`medium`·`small`·`base`)을 고르면 같은 주소의 `ggml-<모델>.bin` 을 받는다.
   - 받아쓰기는 맥의 whisper.cpp 로만 한다. 녹음은 맥 밖으로 나가지 않는다(1.231 부터 외부 API 방식 없음).
3. 쓰기: 마이크 버튼(PC 는 `⌥ Space`)으로 음성 모드를 켜고 끈다. 음성 모드에서 `Enter` 는 전송, `Esc` 는 리셋. 끌 때 남은 글은 입력창으로 간다. 설정 → 음성 → 이 기기에서 단축키(`Ctrl ⇧ Space`·끔), 마이크, 즉시 받아쓰기를 고른다.
4. 즉시 받아쓰기(이 기기, 기본 켬): 말하는 동안 브라우저의 받아쓰기가 글을 흐리게 먼저 보여 주고, 맥의 받아쓰기가 끝나면 그 글로 바뀐다. 이 받아쓰기는 브라우저 회사(Apple·Google)의 서버를 거칠 수 있으니, 녹음을 맥 밖으로 내보내고 싶지 않으면 끈다.

설정(계정에 저장, 모든 기기 공통):

| 항목 | 기본 | 이유 |
|---|---|---|
| 변환 방식 | 맥(whisper.cpp) | 녹음이 맥 밖으로 나가지 않고, 키·요금이 없다 |
| 모델 | large-v3-turbo q5 | 맥 미니에서 7초 한국어 말을 약 1.9 s 에 받아쓰고, 용어를 잘 알아듣는다 |
| 언어 | 한국어 | 자동 감지는 약 2초 더 걸리고 짧은 말에서 언어를 잘못 고를 수 있다 |
| 잡음 줄이기 | 켬 | 시끄러운 곳 대비. 조용한 곳에서는 끄는 편이 더 정확할 수 있다(아래 한계) |
| 말 다듬기 | 켬 | 음·어·그러니까 같은 군말, 되풀이, 문장 부호를 규칙으로 정리(약 5 ms). 원문은 따로 남는다 |
| 용어 사전 | 비어 있음 | 한 줄에 하나. 받아쓰기에 힌트로 주고(600자까지), 결과를 그 표기로 고친다(`claude bridge` → `claude-bridge`) |

- 받아쓴 원문과 다듬은 글은 맥의 `~/.claude-bridge/voice.log`(JSONL, 512 KB 넘으면 뒤쪽 절반)와 설정 → 음성 → 최근 결과(이 브라우저, 20개)에서 비교한다.
- `whisper-server` 는 처음 쓸 때 127.0.0.1 의 빈 포트에 떠서 10분 쓰지 않으면 꺼진다. 처음 한 번은 모델을 읽느라 몇 초 더 걸린다.
- 한계: 웹 페이지라 다른 앱 위에서 쓰는 전역 단축키는 없다(세션 화면 안에서만). 시간은 마디마다 맥 쪽 약 2 s + 업로드. 폰(특히 iOS)에서 마이크와 즉시 받아쓰기를 함께 쓰면 받아쓰기가 마이크를 가져갈 수 있어, 그러면 즉시 받아쓰기를 저절로 끈다. 합성 음성 시험에서는 RNNoise 가 오히려 몇 낱말을 틀리게 만들었다.

## 동작

- **세션**: 에이전트가 zeropty(받지 못했거나 `--mux tmux` 면 tmux) 안에 `claude` 를 띄우고, 트랜스크립트(`~/.claude/projects/…/<id>.jsonl`)를 읽어 서버로 싱크한다. 입력은 같은 터미널 프로그램으로 넣는다. 호스트 화면에 세션마다 어느 쪽인지 보인다.
- **상태**: 턴과 도구의 시작·끝은 Claude Code 훅으로 안다. 훅은 브리지 세션에만 `--settings` 로 등록하고(`~/.claude/settings.json` 은 건드리지 않는다), 그 맥의 에이전트(`127.0.0.1`)로만 보낸다. 세션은 뜨는 중 → 대기 ⇄ 작업 중 ⇄ 응답 대기 → 끝남 가운데 하나다.
- **글 보내기**: 도구가 도는 중에 보낸 글은 붙잡았다가 도구가 끝나면 한 번에 전달한다. 붙잡힌 글은 "지금 보내기"로 바로 넣거나 "수정"으로 되돌릴 수 있다. 전달한 글이 턴을 시작했는지 5초 뒤 확인하고, 입력칸에 남아 있으면 Enter 를 다시 누른다.
- **결정 카드**: 터미널에 뜬 확인 창(권한 요청, AskUserQuestion, 플랜 승인, 그 밖의 번호·키 창)은 대화에 카드로 뜬다. 권한 카드는 실행할 명령이나 바뀔 내용을 보여 준다. 버튼은 그 선택지가 지금 화면에 있을 때만 누른다. 보고 있지 않은 세션의 카드는 모달로 뜬다. 폴더 신뢰·MCP 동의·모델 전환 창은 자동으로 넘긴다.
- **전부 허용**: 세션 메뉴에서 켜면 에이전트가 권한 요청을 바로 허용하고 허용한 내용을 대화에 남긴다. 설정에 남는 선택지("don't ask again", 프로젝트 단위)는 누르지 않는다.
- **쓰는 중인 글**: 답이 끝나기 전의 글은 터미널 화면에서 읽어 흘려 보인다.
- **중단**: Esc 를 한 번 보내고 멈췄는지 확인해 알린다. 중단된 채 기다리는 세션은 "계속해" 카드로 보인다.
- **설정·새로고침·복제**: 세션 메뉴에서 모델·effort·권한 모드를 바꾸고(모델·effort 는 Claude Code 가 그 사람의 기본값으로 저장한다), 같은 대화를 그 자리에서 다시 열고(작업 중이면 끝난 뒤로 예약), 같은 대화에서 갈라진 새 세션을 만든다. 새 세션을 시작할 때는 그 맥의 폴더를 눌러서 고른다.
- **첨부와 그림**: 사진을 골라·붙여넣어·끌어서 보낸다(8장까지, 줄여서). 세션이 읽은 그림과 HTML 답은 대화 안에 그려진다.
- **목록 정리**: 그룹(그룹 안에 그룹, 3단계까지), 끌어서 순서 바꾸기, 휴면, 지난 기록에서 이어서 하기, 폴더 버리고 종료(휴지통으로), 가벼운 복제(SESSION.md 로 새 세션).
- **칩과 게이지**: PR, AGENTS.md, 스킬, `/btw` 옆길 질문, 컨텍스트·5시간·주간 사용률.
- **알림**: 결정이 필요하거나 백그라운드 작업이 끝나면 알림 센터에 뜨고, 켜 두면 웹 푸시로도 온다(푸시에는 내용이 실리지 않고, 깨어난 서비스 워커가 서버에 묻는다). 답이 없으면 5분·10분 뒤 다시 알린다.
- **그 밖에**: 기본 프롬프트, 사용 통계, 이 기기에 대화 캐시, 색 있는 터미널 화면.
- **맥의 대화 이어 가기**: 새 세션 화면의 "맥의 대화 이어 가기" 에서 그 맥의 Claude Code 대화 가운데 bridge 세션이 아닌 것(터미널이나 다른 도구에서 시작한 것)을 골라, 그 폴더에서 `claude --resume` 으로 이어 간다. 여러 개를 골라 한 번에 가져올 수 있고, `/#/new?adopt=<id>,<id>` 로 미리 고른 채 열 수 있다. 1분 안에 쓰인 대화는 "쓰는 중" 으로 표시하고 먼저 묻는다(같은 대화를 둘이 쓰면 기록이 엇갈린다).
- **세션 잠금**: 세션 메뉴의 "잠그기" 로 비밀번호를 건다. 브라우저는 비밀번호의 해시만 보내고, 서버는 그것을 다시 늘려(PBKDF2) 둔다. 잠긴 세션은 목록에 이름과 상태만 보이고, 대화·쓰는 중인 글·화면·알림 내용·플러그인으로 아무것도 나가지 않는다. 비밀번호로 연 탭에서만 보이고(탭을 닫거나 서버가 다시 켜지면 다시 묻는다), 비밀번호를 잊으면 풀 수 없다.
- **대화 캐시**: 연 대화는 이 브라우저(IndexedDB)에 최근 30개 세션, 세션마다 최근 3,000개 이벤트까지 남아 다시 열면 바로 그려지고 새로 생긴 것만 받는다. 목록도 마지막 모습을 남겨 연결 전에 그린다. 잠긴 세션은 남기지 않는다.
- **폰 몸짓**: 목록의 행을 왼쪽으로 밀면 휴면·종료(끝난 세션은 이어서 열기·지우기)가 나온다. 대화 화면은 왼쪽 끝에서 밀면 목록으로 돌아간다(iOS Safari 에서는 브라우저의 뒤로 가기가 이미 그 몸짓이라 쓰지 않는다).
- **헤드리스 연동 모드**: 기기 화면에서 호스트마다 켜고 끈다. 켜면 에이전트가 그 맥의 Chrome 을 화면 없이(헤드리스) 전용 프로필(`~/.claude-bridge/browser`)로 띄워 연동 페이지를 늘 열어 둔다. 맥의 브라우저에 탭을 열어 두지 않아도 연결된다.
  - 켤 때 서버가 일회용 로그인 코드(5분, 한 번)를 에이전트에 건네고, 헤드리스 Chrome 이 그 코드로 로그인한다. 로그인은 그 프로필에 남고, 연동할 때마다 남은 기간이 7일 아래면 30일로 늘어난다.
  - 그 프로필에서만 사이트 → 127.0.0.1 접근 확인(`LocalNetworkAccessChecks`)을 끄고, 키체인 대신 고정 키로 쿠키를 둔다(`--use-mock-keychain`, 헤드리스는 키체인 창에 답할 수 없다). 그래서 프로필 폴더(0700)가 로그인 정보다.
  - 켜져 있는 동안은 헤드리스 탭이 연동을 맡고 보이는 탭은 기다린다. Chrome 이 죽으면 5초부터 60초까지 늘려 가며 다시 띄우고, 에이전트가 끝나면 같이 닫는다. 메모리를 수백 MB 쓴다.
  - 이 모드를 켠 호스트에서는 "에이전트는 혼자서는 바깥과 통신하지 않는다" 가 성립하지 않는다(에이전트가 띄운 브라우저가 연결한다, PRD P2 예외).
- **에이전트 상태와 자동 복구**: 기기 화면의 "에이전트 상태" 에 연동, 헤드리스 연동 모드, 잠자기 막기, 덮개, 세션, 도구 점검, 자동 업데이트, 에이전트가 정상·확인 필요·문제·꺼짐으로 보이고, 사람이 해야 할 일은 명령과 함께 보인다. 에이전트는 1분마다 스스로 살펴 고칠 수 있는 것을 고친다(죽은 caffeinate 다시 띄우기, 바뀐 덮개 설정 다시 적용, 헤드리스 브라우저가 없거나 2분 넘게 연동하지 않으면 다시 띄우기). 고친 기록은 최근 30개까지 보이고 호스트 로그에도 남는다. "지금 복구" 버튼은 다시 띄우기·다시 적용·다시 점검·(백그라운드 서비스일 때) 세션이 쉬면 에이전트 다시 시작을 한다.
- **잠자기**: 맥이 잠들면 세션이 멈추고 웹과 끊긴다(화면만 꺼지는 것은 괜찮다). 사이트의 기기 화면에서 호스트마다 두 가지를 켜고 끈다. 선택은 그 맥의 `agent.json` 에 남는다.
  - "잠자기 막기": 에이전트가 켜진 동안 `caffeinate -i` 로 잠들지 않게 한다. 권한이 필요 없다.
  - "덮개를 닫아도 켜 두기"(맥북): `pmset -a disablesleep 1`. 관리자 권한이 필요해서, 처음 한 번 그 맥의 터미널에서 `node ~/.claude-bridge/agent.mjs awake setup` 을 실행한다(이 두 명령만 비밀번호 없이 허용하는 `/etc/sudoers.d/claude-bridge-pmset` 를 둔다. 상태는 `awake status`, 되돌리기는 `awake remove`). 에이전트가 꺼지면 원래대로 돌려 둔다. 닫은 채 가방에 넣으면 뜨거워질 수 있다.
- **맥이 다시 켜졌을 때**: 에이전트는 세션이 살아 있는 것을 1분마다 적어 두고, 끝난 세션은 바로 지운다. 켜질 때 터미널이 사라졌는데 12시간 안에 살아 있던 세션은 같은 대화로 다시 연다(많아야 5개). 사람이 끝낸 세션은 다시 열지 않는다.
- **`/clear`**: 대화 id 가 바뀌어도 같은 세션으로 이어진다. 그 뒤의 싱크와 옮기기는 새 대화를 기준으로 한다.
- **이벤트 로그**: 서버는 세션마다 번호 붙은 이벤트 로그를 둔다. 조작 화면은 끊겼다 붙으면 가진 번호 뒤의 것만 받는다. 옮기기와 전환도 대화에 한 줄로 남는다.
- **옮기기**: 보내는 맥이 마지막 싱크를 하고 → 받는 맥이 서버의 사본을 받아 `claude --resume` 으로 열고 → 열린 것을 확인한 뒤 보내는 맥이 세션을 내려놓는다. 받는 맥에서 실패하면 세션은 원래 자리에 남는다.
- **끊겼을 때**: 자동으로 전환하지 않는다. 마지막 호스트가 다시 붙기를 기다리면서, 다른 호스트로 전환할지 묻는다. 연결된 호스트가 없으면 그렇다고 알린다.
- **돌아가기**: 전환한 뒤 원래 호스트가 돌아오면 그 호스트는 세션을 다시 돌리지 않는다. 돌아가기를 고르면 그 호스트의 데이터를 서버의 최신 사본으로 덮어쓰고 옮긴다(덮어쓰기 전 사본은 `~/.claude-bridge/overwritten/`).
- **작업 폴더**: 통째로 싱크하지 않는다.
  - git 저장소가 아니면 `SESSION.md`·`AGENTS.md`·`CLAUDE.md` 의 내용을 싱크해 받는 맥에 써 넣는다.
  - 작업 폴더 자체나 1단계 하위 폴더가 git 저장소면 브랜치·커밋 sha·원격 주소를 싱크하고, 받는 맥에서 그 브랜치·커밋을 불러온다(없으면 clone). 받는 맥에 커밋 안 된 변경이 있으면 건드리지 않고 알린다.
  - 브랜치가 `main`·`develop`·`master` 가 아니면 싱크할 때 자동으로 push 한다(강제 push 없음). 세션마다 끌 수 있다.

## 점검

에이전트는 켜질 때, 세션을 시작하기 직전, 그리고 주기적으로(문제가 있으면 1분, 없으면 10분마다) 이 맥을 점검한다. 결과는 터미널에 찍히고, 조작 화면의 호스트 화면 맨 위에 해결 방법과 함께 보인다("다시 점검" 버튼으로 바로 다시 돌릴 수 있다). 고치면 에이전트를 다시 켜지 않아도 반영된다.

| 점검 | 문제일 때 | 세션 시작 |
|---|---|---|
| zeropty | 아직 받지 못함·실행 안 됨 → 새 세션은 tmux 로(에이전트가 30분마다 다시 받아 본다) | 막지 않음 |
| tmux | 설치 안 됨 → `brew install tmux` | zeropty 가 되면 경고만, 아니면 막음 |
| claude | 실행 안 됨 → 설치 안내 | 막음 |
| claude 버전 | `--session-id`·`--resume` 이 없는 옛 버전 → `claude update` | 막음 |
| claude 로그인 | 로그인 안 됨 → 터미널에서 `claude` 실행 후 `/login` | 막음 |
| 에이전트 폴더, claude 기록 폴더 | 쓸 수 없음 | 막음 |
| git | 없음(Xcode 명령줄 도구 미설치 포함) → `xcode-select --install`. 브랜치·커밋 싱크와 자동 push 만 빠진다 | 경고 |
| 디스크 | 5GB 미만 경고, 1GB 미만 오류 | 경고 |
| 잠자기 | 맥이 자동으로 잠들게 돼 있음 → 사이트의 기기 화면에서 "잠자기 막기" 를 켜면 에이전트가 켜진 동안 잠들지 않는다 | 경고 |
| 브라우저 | Chrome 없음(Safari 는 `127.0.0.1` 연결을 막을 수 있음) | 경고 |

그 밖에:

- `node ~/.claude-bridge/agent.mjs doctor` 는 점검만 하고 끝낸다(아무것도 만들지 않는다).
- 포트가 이미 쓰이고 있으면: 이미 켜진 에이전트면 그렇다고 알리고, 다른 프로그램이면 다음 빈 포트로 옮긴다.
- 새 세션의 작업 폴더가 없거나, 폴더가 아니거나, 읽을 권한이 없으면(데스크탑·문서·다운로드의 macOS 권한 포함) 무엇이 문제인지 알려 준다.
- 에이전트가 서버가 내주는 것과 다른 버전이면 호스트 화면에 설치 명령과 함께 알린다.
- 연동 페이지는 Chrome 이 있으면 Chrome 으로 열고, 45초 안에 붙지 않으면 터미널에 확인할 것을 알려 준다. Safari 에서 열면 Chrome 으로 열라고 안내한다.

## 로그

에이전트가 남기는 로그는 연동 페이지를 거쳐 서버로 올라가, 사용자·호스트별 파일(`<BRIDGE_DATA>/u/<사용자>/hosts/<호스트>.log`)에 쌓인다. 연결이 끊긴 동안의 로그(최근 1,000줄)는 다시 붙을 때 올라간다.

- 한 줄에 시각, 수준(info·warn·error), 출처(agent·page·server), 하던 일(new·open·send·move·push·link …), 세션, 내용이 들어간다.
- 조작 화면에서 호스트를 누르면 그 호스트의 로그를 본다. 경고 이상·오류만으로 거르고, 세션 메뉴의 "이 세션의 로그" 로 한 세션만 볼 수 있다.
- 서버 운영자는 서버 출력에서 같은 줄을 `user=<계정> host=<호스트 이름>` 과 함께 본다.
- 보낸 글의 내용은 로그에 남기지 않는다(길이만). 맥에도 `~/.claude-bridge/agent.log` 로 남는다.

## 상태 보기

조작 화면에서 호스트를 누르면 로그 위에 그 호스트의 상태가 나온다(10초마다 갱신).

- **연결**: 언제부터 붙어 있는지, 몇 번째 연결인지, 서버 ↔ 에이전트 왕복 지연.
- **에이전트**: 버전, 켜진 시간, 메모리, `tmux`·`git`·`claude` 버전(없는 도구는 오류로 표시), 맥의 부하, 마지막으로 받은 명령.
- **연동 탭**: 앞에 보이는지 백그라운드인지, 밀린 메시지 수, 재시도 횟수, 브라우저.
- **세션별**: 상태, 서버 사본과 맥의 트랜스크립트가 몇 줄 차이 나는지, 마지막 싱크, push 실패.
- **응답 없음**: 연동 탭은 붙어 있는데 에이전트가 50초 넘게 상태를 보내지 않으면 호스트가 "응답 없음" 이 되고 로그에 남는다.

에이전트는 15초마다 상태를 보낸다. `BRIDGE_ADMIN_LOGINS` 에 든 계정은 운영자로서 첫 화면 아래 "운영 현황" 에서 모든 사용자의 호스트·상태·로그를 본다. 대화 내용은 보지 못한다.

## 접근 관리

운영 화면의 "모델 목록" 에서 새 세션의 모델 목록을 맥의 Claude Code 모델 목록과 맞춘다. 켜 두면(기본) 6시간마다 연결된 맥 한 대에 묻고(프롬프트 없이 `initialize` 만, 토큰을 쓰지 않는다), "지금 확인" 으로 바로 물을 수 있다. 목록은 `DATA/models.json` 에 남는다.

허용되지 않은 계정이 GitHub 로 로그인하면 "승인을 기다리는 중" 이 보이고, 그 계정이 운영자의 **접근 관리** 페이지(첫 화면의 운영 현황 → 접근 관리)에 대기로 올라온다.

- 운영자는 대기 계정을 허용하거나 거부하고, 허용한 계정을 회수하고, 계정 이름으로 미리 추가할 수 있다.
- 회수하면 그 계정의 로그인과 연동·조작 연결이 바로 끊긴다.
- `GITHUB_ALLOWED_LOGINS` 와 `BRIDGE_ADMIN_LOGINS` 에 든 계정은 서버 설정으로 허용된 것이라 페이지에서 바꿀 수 없다. 운영자는 허용 목록에 없어도 로그인된다.

## 끊기지 않는 배포

서버를 바꿀 때 요청이 실패하지 않는다. 새 서버를 먼저 띄우고 옛 서버를 나중에 끄는 방식(Docker Swarm 의 `start-first`)으로 올린다.

1. 새 서버가 뜨면서 데이터 폴더에서 돌고 있는 서버를 발견하고 상태를 요청한다.
2. 옛 서버는 하던 일을 마치고 상태를 디스크에 다 쓴 뒤 쓰기를 멈춘다. 그동안 들어온 요청은 붙잡아 둔다.
3. 새 서버가 상태를 읽고 뜨면, 옛 서버는 꺼질 때까지 붙잡아 둔 요청과 새 요청을 모두 새 서버로 넘긴다.
4. 열려 있던 스트림은 곧바로 다시 붙고, 맥이 다시 붙는 짧은 순간의 요청은 실패시키지 않고 기다린다.

두 서버가 같은 상태를 동시에 쓰는 일은 없다. 돌고 있는 서버가 없으면(처음 켤 때, 옛 서버를 먼저 끄는 배포) 바로 시작한다. 이미지의 `HEALTHCHECK` 가 통과한 뒤에만 새 컨테이너가 트래픽을 받는다. 구현은 `server/handover.mjs`.

배포 중에도 맥에서 도는 세션은 영향을 받지 않는다. 세션은 맥의 zeropty·tmux 에서 계속 돌고, 에이전트는 서버에 다시 붙은 뒤 그 사이의 대화를 이어서 올린다.

## 서버 올리기

```sh
docker build -t claude-bridge . && docker run -p 4300:4300 -v bridge-data:/data \
  -e BRIDGE_ORIGIN=https://bridge.example.com \
  -e GITHUB_CLIENT_ID=… -e GITHUB_CLIENT_SECRET=… -e GITHUB_ALLOWED_LOGINS=alice,bob claude-bridge
```

| 환경 변수 | 뜻 |
|---|---|
| `BRIDGE_ORIGIN` | 사이트의 공개 주소. HTTPS 여야 한다 |
| `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET` | GitHub OAuth 앱. 콜백은 `<BRIDGE_ORIGIN>/api/auth/github/callback` |
| `GITHUB_ALLOWED_LOGINS` | 처음부터 허용할 GitHub 계정(쉼표 구분). `*` 는 누구나. 비워 두고 접근 관리 페이지에서만 허용해도 된다 |
| `BRIDGE_ADMIN_LOGINS` | 운영자 GitHub 계정(쉼표 구분). 접근을 관리하고, 모든 사용자의 호스트 상태와 로그를 본다 |
| `BRIDGE_DATA` | 사본을 두는 폴더(기본 `./data`, 이미지에서는 `/data`) |
| `PORT` | 기본 4300 |
| `BRIDGE_DEMO` | `1` 이면 공개 데모를 켠다: 로그인 화면의 "데모로 둘러보기" 한 번으로 맥 없이 정해진 데모 화면을 둘러본다(앱 심사용). 기본은 끔 |
| `BRIDGE_SOURCE_URL` | 화면의 "소스 코드" 링크(AGPL 13조). 기본 `https://github.com/CreatiCoding/agent-bridge`, http(s) 주소만 |
| `SKILLS_GITHUB_TOKEN` | `/skills` 를 켠다. 스킬 마켓플레이스 저장소를 읽는 읽기 전용 토큰(fine-grained, 그 저장소만 Contents: Read). 없으면 `/skills` 는 꺼진 상태로 안내한다 |
| `SKILLS_REPO` | 스킬 마켓플레이스 저장소(`owner/repo`)의 서버 기본값. 자기 저장소를 정하지 않은 모든 사용자가 이걸 읽는다. 기본은 비어 있다 |

`/skills` 는 로그인한 사용자에게 **자기** 스킬 저장소의 카드·상세(SKILL.md)와 설치 명령을 보여 준다. 저장소는 사용자마다 설정 → 더 보기 → 스킬 저장소에서 정한다(`owner/repo`). 서버의 App·토큰으로 남의 저장소를 읽지 않도록 **owner 가 자기 GitHub 로그인과 같은 저장소만** 넣을 수 있고(대소문자 무시), Apple 로그인·데모 계정은 정할 수 없다. 개인 설정이 있으면 그게 `SKILLS_REPO` 보다 우선이다. 다른 사용자의 저장소는 보이지 않고, 로그인 없이 열리는 `/skills/version` 은 코드 해시(`code`)만 내준다. 설치는 GitHub 를 거치므로 그 저장소에 접근할 수 있는 사람만 된다. 설치 명령의 `/skills/install.sh?repo=owner/repo&t=…` 는 서버 비밀로 만든 서명(`t`)이 붙어 있어야 받을 수 있고, 그 서명은 `/api/skills` 가 그 저장소를 쓰는 사람에게만 준다. 서명이 없거나 틀리면, 또는 이제 아무도 쓰지 않는 저장소면 404 다. `marketplace.json` 의 경로(`pluginRoot`, `source`, `name`)는 평범한 경로 조각만 받고, 저장소 밖을 가리키는 스킬은 건너뛴다. 이름이 바뀌었거나 옮겨진 저장소(GitHub 의 301)는 따라가지 않고 "저장소를 찾을 수 없어요"라고 안내한다.

사용자마다 호스트와 세션이 분리된다. 서버는 대화 사본을 디스크에 평문으로 두므로, 서버를 믿을 수 있는 사람이 운영해야 한다.

### 보안 모델

자기 서버를 올리기 전에 이 시스템이 무엇을 믿는지 알아 둔다.

- **`BRIDGE_ORIGIN` 은 꼭 정하고, HTTPS 리버스 프록시 뒤에서만 운영한다.** 이 값이 없으면 서버는 요청의 `Host`·`X-Forwarded-Proto` 를 믿고 자기 주소(설치 명령, 로그인 콜백, 다른 출처 검사)를 만든다. 서버 포트를 인터넷에 바로 열지 않는다.
- **처음 설치(`curl -fsSL <사이트>/install.sh | bash`)는 서버를 믿는 일이다.** 그때 받은 에이전트와 `agent/keys.mjs`(공개키)를 맥이 믿는다. 그 뒤 업데이트는 그 키의 서명이 맞을 때만 깔린다(위 "자기 서명 키 만들기").
- **에이전트는 서버 말고 GitHub 에서도 하나를 받는다: zeropty.** 주소·버전·SHA-256 은 서명된 에이전트 파일(`agent/mux.mjs`)에 고정돼 있어, 받은 묶음의 해시가 다르면 아무것도 설치하지 않는다(그러면 tmux 를 쓴다). 업데이트로 버전이 바뀔 때만 다른 것을 받는다. 이 일로 모든 맥의 홈에 `~/.claude-bridge/zeropty/`, 서명을 바꾼 claude 사본 `~/.zeropty/tty/`(약 260MB), 소켓 `~/.zeropty/mux.sock`(0600, 같은 사용자만)이 생긴다. 원치 않으면 `--mux tmux` 로 새 세션도 tmux 로 연다(받기는 그대로 하지만 쓰지 않는다).
- **서버가 털리면 연결된 맥에 지시를 보낼 수 있다.** 서명 확인은 새 코드가 깔리는 것을 막을 뿐이다. 서버는 원래 맥의 Claude 세션을 열고 메시지를 보내는 곳이라, 서버를 가진 사람은 연결된 맥에서 그 사용자 권한으로 Claude 를 움직일 수 있다. 서버는 그만큼 믿을 수 있는 곳에 둔다.
- **`/skills` 는 토큰보다 GitHub App 을 권한다**(`SKILLS_GITHUB_APP_ID`·`SKILLS_GITHUB_APP_KEY`). App 의 설치 토큰은 읽는 저장소 하나와 Contents 읽기로 좁혀지고 한 시간 뒤 끝난다. 토큰(`SKILLS_GITHUB_TOKEN`)을 쓰면 fine-grained 로, 그 저장소만 Contents: Read 로 만든다.
- **로그인 없이 열리는 곳은 최소한만 내준다.** `/api/health` 는 `ok`·`version`·`instance` 만, 서버가 어떻게 도는지(`BRIDGE_ORIGIN` 유무, root 실행, 에이전트 서명)는 운영자의 `/api/admin/overview` 에서 본다.
- **포크해서 iOS 앱을 빌드하면 Team ID 와 번들 ID 를 바꾼다.** `ios/Bridge.xcodeproj/project.pbxproj` 의 `DEVELOPMENT_TEAM`·`PRODUCT_BUNDLE_IDENTIFIER`, `scripts/testflight.sh` 의 `teamID`, Apple 로그인을 쓰면 `APPLE_CLIENT_ID` 환경 변수. 원 운영자의 값으로는 서명·로그인·알림이 되지 않는다.

### 자기 서명 키 만들기

맥의 에이전트는 서버가 보낸 새 버전을 그대로 깔지 않고, `agent/keys.mjs` 에 적힌 공개키로 서명이 맞을 때만 받는다. 그래서 서버가 뚫려도 서명 없는 코드가 맥에 깔리지 않는다. 이 저장소의 `keys.mjs` 는 원 운영자의 키라, 포크해서 자기 서버를 올리면 자기 키를 만들어야 자동 업데이트가 된다.

```sh
node scripts/sign-agent.mjs --init   # 새 키 쌍: 개인 키는 ~/.claude-bridge-signing/agent-ed25519.pem(0600), 공개키는 agent/keys.mjs
node scripts/sign-agent.mjs          # agent/ 를 고칠 때마다 서명해 agent/agent.sig 를 같은 커밋에
```

- 개인 키는 저장소·서버에 두지 않는다. 다른 경로를 쓰려면 `CLAUDE_BRIDGE_SIGN_KEY=<파일>`. 이미 있는 키 파일은 덮어쓰지 않는다.
- `keys.mjs` 도 서명되는 에이전트 파일이다. 서버가 키를 바꿔치기하면 서명이 맞지 않아 맥이 거절하고, 키를 바꾸는 업데이트는 지금 믿는 키로 서명해야 맥에 간다.
- 맥은 설치할 때 받은 `keys.mjs` 를 믿는다. `--init` 전에 다른 서버에서 설치한 맥은 새 키의 업데이트를 받지 않으니 다시 설치한다.
- `npm test` 는 `agent/agent.sig` 가 지금 파일·키와 맞지 않으면 실패한다.

## 개발

```sh
PORT=4399 BRIDGE_DEV_LOGIN=1 GITHUB_ALLOWED_LOGINS=tester node server/server.mjs   # /api/auth/dev?login=tester 로 로그인
CLAUDE_BRIDGE_HOME=/tmp/agentA node agent/agent.mjs http://localhost:4399 --port 4398 --name MacA
```

`BRIDGE_DEV_LOGIN=1` 은 GitHub 없이 로그인하게 하므로 공개 서버에 넣지 않는다.

조작 페이지를 고칠 때:

```sh
cd ui && corepack yarn install
corepack yarn dev      # http://localhost:5199 — /api 는 4399 의 서버로 보낸다(BRIDGE_URL 로 바꿀 수 있다)
corepack yarn build    # tsc 타입 검사 + ui/dist. 서버는 이것을 / 에서 내준다
```

- `npm test` 는 터미널 화면 판독 규칙과 트랜스크립트 → 이벤트 변환을 확인한다(`test/unit/`).
- `test/e2e-lock.mjs` 는 세션 잠금(다른 기기·API 에서 안 보임, 틀린·맞는 비밀번호, 다시 잠그기, 잠금 없애기), 대화 캐시, 폰 몸짓을 확인한다.
- `test/e2e-adopt.mjs` 는 bridge 밖에서 만든 대화를 가져와 이어 가는 것과, 에이전트를 끄고 터미널을 없앤 뒤(다시 켜진 맥처럼) 세션이 같은 대화로 되살아나는 것을 확인한다.
- `test/e2e-ui.mjs` 는 조작 페이지(`/`)로 새 세션·답·흐린 말풍선·권한 카드·이름·설정·터미널 화면·PC 화면·통계·기기·종료와 이어서 열기를 확인한다(에이전트 하나, 실제 `claude` 세션). 시스템 Chrome 으로 돌리려면 `CHANNEL=chrome`.
- `test/e2e-accounts.mjs` 는 Claude 계정(설정 → Claude 계정)을 더하고, 로그인 주소를 받고, 세션을 다른 계정으로 옮겼다가 돌아와도 대화를 기억하는지, 계정을 빼는 것을 확인한다. 두 번째 실제 로그인 없이 돌리는 방법은 파일 머리에 있다.
- `test/e2e-tabs.mjs` 는 조작 페이지(`/`)를 연 한 브라우저의 여러 탭을 확인한다: 연동하던 탭이 멈추면 기다리던 탭이 넘겨받는지, 넘겨받은 탭을 닫으면 곧바로 이어지는지, 기다리던 탭을 새로고침하면 그 탭이 넘겨받는지. `claude` 세션은 띄우지 않는다.

e2e 는 Playwright 가 필요하다(이 저장소의 의존성은 아니다). 예: `PLAYWRIGHT=<playwright 의 index.mjs> AGENT_A=/tmp/agentA WORK=<작업 폴더> SHOTS=<스크린샷 폴더> node test/e2e-ui.mjs`. 파일마다 필요한 환경 변수는 파일 머리에 있다.

## 플러그인

사람마다 자기 bridge 에 넣었다 뺐다 하는 기능이다. 메뉴(⋯) → 플러그인에서 켜고, 끄고, 뺀다. 설정과 실행은 사용자별로 따로다.

### Slack

Slack 전용 채널에서 세션을 이어서 한다. 각자 **자기 Slack 앱과 자기 전용 채널**을 쓴다.

- 한 세션은 **한 번에 한 곳**(브릿지 또는 Slack)에서만 작업한다. 세션 메뉴의 "Slack 으로 옮기기" 로 보내고, Slack 스레드의 "브릿지로 옮기기" 로 가져온다.
- Slack 에 있는 동안 브릿지 화면은 읽기 전용이다(배너의 "Slack 스레드 열기"·"브릿지로 가져오기"). 브릿지에 있는 동안 스레드에 쓴 글은 세션에 가지 않고, 쓴 사람에게 브릿지 링크와 "Slack 으로 가져오기" 버튼이 온다.
- 어느 쪽에서 나눈 대화든 브릿지의 세션 화면에 모두 남는다. 스레드에는 옮길 때마다 세션 화면 링크가 남는다.
- Slack 에 있는 세션이 한 말, 권한·질문 카드가 스레드에 올라오고, 카드의 버튼으로 답한다. 스레드에 답하면 그 세션에 전달된다(그림 첨부 포함). 채널에 새 글을 쓰면 Slack 에서 작업하는 새 세션이 뜬다.
- 처음 글을 쓴 Slack 계정에는 연결 링크가 온다. bridge 에 로그인한 브라우저에서 그 링크를 연 계정만 세션을 조작할 수 있다.
- 전용 채널은 설정 창의 "채널 고르기" 로 봇이 들어간 채널 중에서 고른다.
- Socket Mode 라서 공개 URL 을 등록할 필요가 없다. 설정 방법은 시작 가이드의 Slack 단계와 플러그인 창의 "처음 설정하는 방법" 에 있다.
- 앱은 매니페스트가 채워진 링크(`api.slack.com/apps?new_app=1&manifest_json=…`)로 만든다. 앱 만들기·설치·전용 채널 만들기·봇 초대는 "AI 에게 Slack 쪽 준비 맡기기" 프롬프트로 브라우저를 다루는 AI 에게 맡길 수 있다. 이 프롬프트는 토큰을 AI 가 읽거나 넣지 않게 하므로, 토큰 두 개는 사람이 직접 붙여 넣는다.
- 저장할 때 토큰 접두어(`xoxb-`, `xapp-`)를 확인하고, 두 토큰이 서로 바뀌어 있으면 제자리에 넣는다. 봇이 들어간 채널이 하나뿐이면 전용 채널을 비워 둬도 그 채널로 정한다.

플러그인을 만들려면 `server/plugins/` 에 `{ id, name, about, fields, help, start(config, host) }` 를 내보내는 파일을 두고(필드에 `prefix` 를 주면 값의 접두어를 확인한다) `server/plugins.mjs` 의 목록에 넣는다. `host` 로 받은 호출(`send`, `start`, `command`, `find`, `seat`, `summary`, `seatUrl`, `moveTo`)만 쓸 수 있다. 세션을 받아 갈 수 있는 플러그인은 `moveIn`·`moveOut` 을, 고르는 필드(`pick`)가 있으면 `choices(config, key)` 를 내보낸다.
