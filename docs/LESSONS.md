# 예전 Slack 기반 도구에서 배운 것

claude-bridge 는 세션을 붙이고, 읽고, 조작하는 방식을 예전 Slack 기반 도구(이하 "예전 도구")에서 가져온다(PRD P7). 이 문서는 그 도구의 명세에 적힌 시행착오 가운데 무엇을 어디에 옮겼는지, 옮기면서 무엇이 달라졌는지, 아직 옮기지 않은 것은 무엇인지를 적는다.

구조는 바꾸지 않았다. 세션은 맥에서만 돌고(P1), 맥의 에이전트는 `127.0.0.1` 에서만 듣고 바깥과는 연동 탭이 잇고(P2), 서버는 사본을 두고 중계만 한다(P4). 예전 도구의 브로커가 하던 일은 그 맥의 에이전트가 하고, 웹 앱이 하던 일은 조작 페이지가 한다.

| 예전 도구 | claude-bridge |
|---|---|
| 브로커(세션 상태, 다이얼로그, 주입) | 로컬 에이전트 `agent/` |
| 채널 심(MCP)으로 글과 권한을 주고받음 | 쓰지 않는다. 글은 tmux 키로, 권한은 화면의 확인 창으로 |
| 훅 전달기 → unix socket | 훅 → `curl` → 에이전트의 `127.0.0.1/hook` |
| 스레드별 이벤트 로그 | 세션별 이벤트 로그(서버 디스크) |
| 웹 앱 | 조작 페이지 `ui/` |

채널 심을 쓰지 않는 이유: 에이전트는 의존성 없이 파일 몇 개로 내려받아 실행하는데, 채널 심은 MCP SDK 와 개발 채널 플래그가 필요하다. 그래서 예전 도구가 "채널이 안 될 때의 대체 경로"로 다듬어 둔 규칙(키 입력으로 전달, 화면의 확인 창을 읽어 누르기)이 여기서는 주 경로다.

## 1. 세션 상태는 훅으로 안다

## 2. 글을 넣는 일

| 배운 것 | 근거 | 옮긴 곳 |
|---|---|---|
| 도구가 도는 중에 온 글은 붙잡았다가 도구가 끝나면 한 번에 전달한다. 여러 개면 빈 줄로 이어 하나로 | REQ-F-011, REQ-F-012 | `inject`, `hold`, `releaseHeld` |

채널이 없어서 달라진 점: 예전 도구는 권한을 기다리는 중에도 채널로 글을 전달하지만, 키 입력은 그 확인 창에 타이핑된다. 그래서 권한·키 확인 창이 떠 있으면 글을 붙잡는다.

## 3. 터미널의 확인 창

| 배운 것 | 근거 | 옮긴 곳 |
|---|---|---|
| 번호를 누르는 것은 그 선택지가 지금 화면에 있을 때만 안전하다. 오래된 버튼이 숫자를 프롬프트에 쳐 넣어 "1" 이 메시지로 간 적이 있다. 키를 누르는 코드는 한 곳뿐이고 매번 화면을 확인한다 | `dialog.ts` 머리말 | `agent/dialog.mjs` `DialogDriver` |

| 여러 질문 창 위의 탭 띠(`← ☐ … ✔ Submit →`)는 질문이 아니다 | §4.3.6 6단계 | `parseDialog` |

## 4. 쓰는 중인 글

Claude Code 는 글 덩어리를 다 쓴 뒤에야 트랜스크립트에 적는다. 그 전의 글은 화면에서 읽는다(§4.3.10, `agent/preview.mjs`).

- 색(SGR)까지 읽어 굵게와 인라인 코드, 코드 펜스를 markdown 으로 되살린다.
- 터미널 폭에서 꺾인 줄을 다시 잇는다(다음 줄의 첫 낱말이 윗줄에 들어갔을 폭이면 화면이 꺾은 것이다).
- 덩어리 머리(`⏺`)가 화면 위로 밀려나면, 앞서 보인 글의 끝 40자를 화면에서 찾아 그 뒤를 잇는다.
- 글이 사라진 것은 "생각 중"이지 지워진 것이 아니다. 보이던 글을 그대로 둔다.
- 화면은 220열 × 80행으로 띄운다. 높을수록 덩어리가 많이 보인다.

## 6. 옮기면서 새로 알게 된 것

예전 도구의 명세에 없고, 이 저장소의 e2e 를 돌리다 찾은 것이다.

- **"Yes, and switch to auto mode"**: 지금 Claude Code 의 확인 창에 있는 선택지다. 기존 분류는 이것을 "이번만 허용"으로 읽는다. 모드를 바꾸는 선택지로 분류했다(`classifyOption`).
- **`● high · /effort`**: 입력칸 위 줄 오른쪽 끝의 힌트다. 쓰는 중인 글의 마지막 줄로 읽혔다. 틀의 일부로 건너뛴다(`EFFORT_HINT_RE`).
- **프롬프트 제안**: 입력칸에 다음 프롬프트가 흐린 글로 그려지면 빈 프롬프트가 비어 보이지 않는다. 브리지 세션에서는 끈다(`CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION=false`).
- **컨텍스트 남은 양**: `Context left until auto-compact: 12%` 는 "left" 와 숫자 사이가 21자다. 10자까지만 허용하는 규칙은 이것을 12% 사용으로 읽는다. 30자로 넓혔다(`detectContext`).
- **뜨는 동안의 훅**: 세션을 목록에 넣기 전에 띄우면 SessionStart 와 첫 프롬프트의 훅을 버린다. 서버도 세션을 만들기 전에 에이전트에게 띄우라고 하면 그사이의 보고를 버린다. 양쪽 모두 먼저 등록하고 띄운다.
- **옮기는 중의 보고**: 받는 맥은 열자마자 말하기 시작한다. 그 세션의 호스트가 아직 보내는 맥으로 적혀 있으면 서버가 받는 맥에게 "내려놓으라"고 한다. 옮기는 중에는 받는 맥도 그 세션을 대신해 말할 수 있게 했다(`owns`).
- **Esc 두 번**: 중단이 안 된 것 같아 Esc 를 한 번 더 보내면, 그사이 새 글이 시작한 다음 턴을 끊는다. 한 번만 보낸다(REQ-F-035 가 이미 그렇게 정해 두었다).

- **재시작은 쉴 때만**: 에이전트가 스스로 새 버전으로 바뀔 때(자동 업데이트) 턴·붙잡은 글·열린 카드는 그 프로세스의 기억에만 있다. 모든 세션이 쉴 때까지 기다렸다가 바꾼다(REQ-R-008 과 같은 이유). 새 파일은 에이전트가 직접 받지 않고 연동 탭이 건넨다(P2).

- **상태 줄과 '중단됨'**: 게이지를 위해 상태 줄을 등록하자, 입력칸 아래에 그 한 줄이 생기면서 "Interrupted 뒤에 아무것도 없다"는 판정이 깨졌다. 입력칸 아래는 상태 영역이라 판독에서 뺀다(`stuckState`).
- **다시 여는 동안 온 글**: 새로고침으로 터미널이 잠깐 없는 사이에 보낸 글은 "세션이 돌고 있지 않다"며 버려졌다. 붙잡았다가 돌아온 세션에 넘긴다. 테스트가 "답이 왔다"를 이전 답으로 통과시켜 가려져 있었다(답마다 다른 표식을 쓰게 고쳤다).
- **권한 모드는 다시 열 때 사라진다**: `--resume` 은 그 사람의 기본 모드로 뜬다. 새로고침·옮기기에 `--permission-mode` 를 넘겨 이어 간다(REQ-F-096).
- **첨부한 그림의 자리**: 작업 폴더 밖에 저장하면 Claude Code 가 읽을 때마다 권한을 묻는다. 그 폴더를 `--add-dir` 로 넘긴다.
- **`on*` 속성 핸들러의 반환값**: `a && b()` 한 줄짜리 핸들러는 `a` 가 거짓이면 `false` 를 돌려주고, 그러면 그 입력이 취소된다(입력칸에 글자가 안 쳐졌다). `h()` 가 반환값을 버리게 했다.
- **테스트가 사람의 환경을 건드린다**: `/effort`·`/model` 은 그 사람의 기본값으로 저장되고, 폴더 입력이 덮어써지면 세션이 홈 폴더에서 돈다. e2e 는 권한 모드만 바꾸고, 세션이 고른 폴더에서 시작했는지 확인한다.

## 7. 예전 도구의 웹 앱에 있고 여기 없는 것

그 웹 앱의 코드를 처음부터 끝까지 대조해 옮겼다. 남은 것은 Slack 이 있어야 뜻이 있는 것과, 구조가 달라 다른 모양이 된 것이다.

| 항목 | 여기서는 |
|---|---|
| Slack 스레드 칩, 메시지의 `via slack` 표시, 리액션으로 보이는 전달 상태 | Slack 을 쓰지 않는다. 전달 상태는 붙잡힌 글·흐린 말풍선으로 보인다 |
| reply 도구가 올린 파일·그림, 텍스트 파일 첨부 보기 | 채널(MCP)이 없어 reply 도구가 없다. 도구 결과의 그림과 터미널에 붙인 그림은 보인다 |
| 이어서 하기(맥에 있는 다른 대화 목록) | 브리지가 연 세션만 다룬다. 끝난 세션은 "지난 기록"에서 다시 연다 |
| 터미널 화면을 PNG 로 | 색을 그대로 살린 글로 보인다(맥에 Chromium 이 필요 없다) |
| 전부 허용을 켤 때 터미널을 manual 모드로 돌리기 | 권한 창을 화면에서 읽으므로 모드와 무관하게 창이 뜨면 허용한다 |
| 플러그인 새 버전 알림, 브로커 꺼짐 안내, 이전 관리 화면 | 해당하는 것이 없다. 에이전트는 스스로 업데이트한다 |

확인하지 못한 것: 웹 푸시는 실제 브라우저·폰에서 받아 보지 못했다(구독·전송 코드와 서비스 워커만 있다). 5분·10분 뒤 다시 알리기는 시간을 기다려 확인하지 않았다. 폴더 이름 자동 완성과 끌어서 순서 바꾸기는 e2e 에 없다.

## 8. 화면은 닮게 다시 쓰지 말고 그대로 가져온다

조작 페이지를 예전 도구와 "같게" 다시 썼더니 메뉴의 여백, 현재 값의 체크 표시, 항목 하나 같은 사소한 차이가 끝없이 나왔다. 닮게 쓴 코드는 원본이 바뀔 때마다 다시 어긋난다.

- 그래서 한동안 예전 도구의 화면 파일을 고치지 않고 그대로 가져와 썼고, 차이는 서버가 흡수했다. `server/cs.mjs` 가 bridge 의 이벤트를 그 도구의 이벤트와 Slack 블록 카드로 옮겼다.
- bridge 에만 있는 것(맥 목록, 옮기기, 다른 맥에서 이어 하기, 중계)은 가져온 화면 위에 덧댔다.
- 이 방식은 11절에서 조작 페이지를 새로 쓰면서 그만두었고, 가져온 화면도 없앴다.
- 가져온 화면이 기대하는 모양을 눈으로 추측하지 않는다. 옆길 질문 카드는 서버가 `ephemeral` 로 보내서 안 보였다(원본은 보통 메시지를 고쳐 쓴다). 권한 모달은 "화면에 없는 세션" 에만 뜬다. 원본 broker 가 무엇을 보내는지 읽고 그대로 보낸다.
- 끝까지 남는 차이: 세션이 사는 맥이 여러 대라 목록에 기기 구역이 있고, 맥이 꺼져 있으면 보낼 수 없다. 화면 캡처는 PNG 대신 SVG 로 그린다.

## 9. Slack 은 플러그인으로, 사람마다 따로

예전 도구는 봇 하나가 한 사람의 맥에서 돈다. bridge 는 서버를 여럿이 쓰므로 봇을 서버에 하나 두면 안 된다.

- 사람마다 자기 Slack 앱(봇 토큰·앱 토큰)과 채널을 넣는다. 서버는 사용자별로 Socket Mode 연결을 하나씩 든다. 한 사람의 잘못된 토큰은 그 사람 것만 멈춘다.
- 카드는 새로 만들지 않았다. 예전 화면에 주려고 만들었던 Slack 블록(`server/cs.mjs`)을 그대로 Slack 에 올리고, 버튼 값(`<pid>:card …`)도 웹과 같은 `csCommand` 로 처리한다.
- 채널에 있는 누구나 내 맥에서 명령을 돌리게 둘 수는 없다. 처음 보는 Slack 계정에는 링크를 주고, bridge 에 로그인한 사람이 그 링크를 열어야 연결된다.
- 채널의 새 글로 세션을 띄울 때, 세션이 뜨는 동안 나온 말이 스레드를 알기 전에 올라가면 스레드가 둘이 된다. 올리는 일은 한 줄로 세우고, 세션을 띄우는 일도 그 줄에 넣는다.
- 실제 Slack 으로는 시험하지 못했다(쓰던 봇의 Socket Mode 연결을 나눠 가지면 예전 도구가 이벤트를 잃는다). 가짜 Slack(HTTP + WebSocket) 으로 단위 테스트했다.

## 10. 화면이 같아도 서버가 다르면 다르다 (SPEC 대조)

화면 코드를 그대로 가져온 뒤에도, 그 화면이 기대하는 것과 서버·에이전트가 하는 것을 조항별로 대조하니 차이가 백여 건 나왔다. 화면이 같다는 것은 겉만 같다는 뜻이었다.

- **같은 버튼이 다른 일을 했다.** "지난 기록 모두 지우기" 는 예전 도구에서 보관 파일만 지우는데, bridge 는 끝난 세션(이어서 할 대화) 전부를 지웠다. 가져온 화면의 버튼마다 "여기서는 무엇을 지우거나 바꾸는가" 를 따로 확인해야 한다.
- **화면이 읽는 값의 모양.** `background` 를 개수(숫자)로 보냈더니 화면은 `.length` 를 읽어 배지가 영영 안 떴다. 필드 이름만이 아니라 타입까지 원본 broker 가 보내는 그대로여야 한다.
- **오류는 상태 코드로 말한다.** 화면의 `api()` 는 2xx 가 아니어야 토스트를 띄운다. 200 에 `ok:false` 를 담아 보내면 빈 창이 열린다.
- **낡은 버튼.** 예전 카드의 Esc 버튼이 아무 확인 없이 Esc 를 보내면 지금 돌고 있는 턴이 끊긴다. 버튼은 "그 카드가 아직 열려 있고, 그 질문이 아직 화면에 있을 때만" 누른다.
- **Esc 는 닫기가 아니라 거부일 수 있다.** 글을 전달하려고 질문 창을 닫는 Esc 가, 그사이 뜬 권한 창에 닿으면 거부가 된다. 권한 창이 보이면 멈춘다.
- **뜨는 중인 터미널에는 치지 않는다.** 폴더 신뢰 같은 시작 창이 떠 있을 수 있다. 붙잡았다가 뜬 뒤에 전달한다.
- **폴더를 버리는 규칙은 넓게 막는다.** 홈 밖, 홈 바로 아래, 휴지통 안, 다른 세션이 쓰는 폴더는 버리지 않는다. `/` 와 홈만 막는 것으로는 `~/projects` 가 통째로 날아간다.
- **두 번 누르기.** 같은 글·같은 버튼은 1.5초 안에 한 번만 처리한다.
- 남은 차이는 `docs/SPEC-GAPS.md` 에 적는다.
- **화면을 더 자주 읽으면 다른 것을 읽는다.** `/btw` 답을 "같은 글이 두 번 보이면 끝" 으로 읽는데, 읽는 간격을 700ms 에서 400ms 로 줄이자 `✶ Answering…` 스피너 줄이 두 번 같게 보여 그것을 답으로 냈다. 화면에서 읽는 규칙은 간격까지가 규칙이다. 스피너 줄은 답이 아니라고 따로 적어야 했다.
- **끝난 세션에 글이 오면 다시 연다.** claude 가 스스로 끝난 세션에 "멈춰 있습니다, 다시 연 뒤 보내세요" 라고 거절하면 사람이 할 일이 두 번이 된다. 받은 글을 붙잡고, 같은 대화로 다시 열고, 뜨면 전달한다.
- **"끝나면" 은 턴만 끝난 것이 아니다.** 끝나면 새로고침이 턴이 없다는 것만 보고 바로 새로고침하면, 화면이 "끝나면" 을 권한 바로 그 이유(백그라운드 작업)를 끊는다.
- **숫자 뒤의 Enter.** 확인 창은 "숫자, 그다음 Enter" 로 눌러 왔다. 질문이 여러 개인 AskUserQuestion 에서는 숫자만으로 답이 되고 바로 다음 질문으로 넘어간다. 뒤따른 Enter 가 두 번째 질문을 첫 줄로 답해 버렸다. 숫자를 누른 뒤 화면의 질문이 바뀌었으면 Enter 를 보내지 않는다. 마지막 질문 뒤에 뜨는 "Submit answers" 는 사람에게 또 묻지 않고 대신 누른다.
- **tmux 에 긴 글을 인자로 주면 조용히 실패한다.** `set-buffer -- <글>` 과 `new-session … <프롬프트>` 는 글이 16KB 쯤을 넘으면 "command too long" 으로 거절된다. 결과를 확인하지 않아서, 아무것도 붙지 않은 입력칸에 Enter 만 치고 "전달했다" 고 기록했다. 긴 글은 파일에 쓰고 `load-buffer` 로 올린다. 명령의 결과는 본다. 큰 SESSION.md 의 가벼운 복제를 e2e 로 돌려 보고서야 드러났다: 작은 입력으로만 시험한 경로는 큰 입력에서 처음 깨진다.
- **짐작으로 만든 조작은 실제 화면에서 틀린다.** 복수 선택 질문을 "번호를 누르고 Enter 로 확정" 이라고 짐작해 만들었다. 실제 Claude Code(2.1.289)에서는 숫자만으로 체크가 켜지고 꺼지며, Enter 는 커서 줄을 다시 토글하고, 제출은 번호 없는 "Submit" 줄까지 내려가서 Enter 다. 체크가 바뀔 때마다 선택지 글이 달라져 카드도 매번 새로 떴다. tmux 에 직접 띄워 키를 하나씩 눌러 보고서야 알았다: 터미널 창을 다루는 코드는 그 창을 실제로 띄워 보고 쓴다.
- **"기다리는 중" 은 "끝났다" 가 아니다.** 턴이 끝났는데 열려 있는 도구를 (중단됨) 으로 닫는 규칙이, 답을 기다리는 AskUserQuestion 까지 실패로 표시했다. 작업 중이 아닌 것과 끝난 것은 다르다.
- **플랜 창의 세 번째 선택지는 "No, keep planning" 이 아니었다.** 지금 버전은 "Tell Claude what to change" 다. 문구로 짝짓고 안 맞으면 원래 문구를 보이게 해 둔 덕에 틀린 이름표가 붙지 않았다.

## 11. 조작 페이지를 bridge 자신의 API 위에 새로 썼다

8절은 "닮게 다시 쓰지 말고 그대로 가져온다" 였다. 가져온 화면은 예전 도구의 프로토콜을 기대해서, 서버가 bridge 의 이벤트를 그쪽 모양(세션 행, Slack 블록 카드, pid·thread 주소)으로 번역해야 했고, 맥이 여러 대인 것·옮기기·전환처럼 bridge 에만 있는 것은 화면 위에 덧대야 했다. 새 조작 페이지(`ui/`)는 그 번역 없이 bridge 의 이벤트와 세션을 그대로 그린다.

- **뜻은 서버 한 곳에 둔다.** 입력칸의 글(`/btw`, `:` 명령 포함)과 메뉴·카드의 명령은 `/api/sessions/<id>/say`·`/do` 로 보내고, 서버 한 곳의 함수(`csSend`, `csCommand`)로 처리한다. Slack 플러그인의 버튼도 같은 함수를 거치므로, 같은 버튼이 자리마다 다른 일을 하는 일(10절 첫 줄)이 생기지 않는다.
- **화면이 읽는 값은 서버가 실제로 보내는 그대로 읽는다.** 짐작한 모양은 틀렸다: 폴더 목록의 항목은 문자열이 아니라 `{ name, git }` 이고, 사용량의 컨텍스트는 토큰 수가 아니라 퍼센트, 리셋 시각은 이미 밀리초였다. 첫 e2e 에서 바로 드러났다.
- **늦게 온 응답은 버린다.** 새 세션 폼이 처음 열 때 홈 폴더 목록을 묻는데, 그 답이 사람이 고른 폴더의 답보다 늦게 와서 고른 폴더를 홈으로 덮었다. 세션이 엉뚱한 폴더에서 떴다. 마지막으로 물은 것의 답만 쓴다.
- **선택자는 늘 같은 값을 돌려줘야 한다.** 저장소에서 값을 고르는 함수가 `?? []` 로 매번 새 배열을 돌려주면 React 가 끝없이 다시 그린다. 빈 목록은 하나(`NONE`)를 같이 쓴다.
- **예전 페이지는 한동안 함께 두었다가 없앴다.** 새 페이지로 옮겨 가는 동안 `/cs`·`/classic` 에 남겨 두고 양쪽 e2e 를 함께 돌렸다. 지금 두 주소는 `/` 로 보낸다.
- **부품은 직접 만든다.** 시트, 메뉴, 토스트, 스위치 같은 화면 부품은 `ui/src/kit/` 에 있다. 의존성은 react 하나로 둔다(P6, 누구나 자기 서버에 올린다).

## 11. 무중단 배포인데 502 가 났다

새 서버를 먼저 띄우고 옛 서버가 요청을 넘겨주는 구조(`server/handover.mjs`)여서 배포 중에 요청이 실패하지 않는다고 적어 두었는데, 배포 중에 누른 복제가 502 를 받았다(2026-10-10). 실패한 요청은 에이전트 로그에 없었다: 에이전트까지 가지 못하고 서버 층에서 끊긴 것이다.

- 옛 서버는 SIGTERM 을 받으면 저장하고 **바로** `process.exit(0)` 했다. 배포 도구가 옛 컨테이너를 멈추라고 한 뒤에도 라우터(Traefik)는 1초 안팎 더 그 컨테이너로 요청을 보낸다. 그 요청은 연결 거부 → 라우터의 502. 페이지는 JSON 이 아닌 502 를 받아 "요청이 실패했어요 (502)" 만 보였다(서버가 낸 오류면 문구가 있다).
- 고침: 넘겨주는 중(draining·proxy)에 종료 신호가 오면 8초 더 떠서 요청을 새 서버로 넘기고 끝낸다(컨테이너 멈춤 유예 10초보다 짧게). 혼자인 서버는 전처럼 바로 끝난다.
- 확인은 "종료 신호를 보낸 뒤 옛 포트로 계속 요청을 보내 보는 것" 으로 했다. 무중단이라는 말은 "교체되는 쪽이 꺼지는 순간" 까지 보고 나서 할 수 있다.
- 이 수정이 담긴 배포 자체는 아직 옛 코드가 도는 서버를 교체하므로 한 번 더 같은 502 가 날 수 있다. 그다음 배포부터 사라진다.
