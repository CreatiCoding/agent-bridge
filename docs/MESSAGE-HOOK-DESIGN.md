# 답 단위 익스텐션 훅과 조용한 답 설계 (REQ-F-850, 1.404)

사용자 요청. 익스텐션은 지금까지 답 안의 코드 블록(`renderer.block`)만 바꿀 수 있었다. 이제 답 하나를 통째로 보고 접거나 바꿀 수 있다. 접은 답은 "새 답" 표시와 알림을 띄우지 않는다. 예: 예약 작업이 할 일 없이 끝나 답 끝에 `[조용히]` 를 쓴 답.

설계 뒤 다른 관점의 적대적 검토를 거쳐 고쳤다(§9).

## 1. 두 갈래

| 갈래 | 누가 판단 | 영향 |
|---|---|---|
| **조용한 답 규칙** `messages.quiet` (extension.yaml, 선언) | 서버(평문 답) · 봉인하는 맥(자기 터미널 규칙, §5) | 화면 접기 + "새 답" 표시 + 알림 웹훅 + Slack |
| **화면 훅** `message.render` (코드, `around` 만) | 익스텐션 코드 | 그 페이지 화면만 |

알림과 "새 답" 표시는 서버가 낸 값(`seq`, 웹훅, Slack)에서 나온다. 그래서 화면 코드만으로는 막을 수 없고, 막는 힘은 선언 규칙에만 준다. **페이지는 서버가 붙인 표지(`quiet`)만 따라 접는다.** 그래서 화면과 알림이 어긋나지 않는다. 화면 훅은 화면만 바꾼다. 규칙이 접은 답은 훅이 펼치지 못한다.

## 2. 선언 규칙 `messages.quiet`

```yaml
messages:
  quiet:
    - suffix: "[조용히]"
      label: 할 일 없음      # 접힌 줄에 보일 말(선택, 40자)
```

- **정규식이 아니라 끝 글자(literal suffix)다.** 서버(Go)와 맥(JS)이 같은 결과를 내야 한다. 끝 글자 비교는 두 곳에서 뜻이 같고, 걸리는 시간이 글 길이에 비례한다(ReDoS 없음).
- `suffix` 조건: 1~40자, 한 줄, 앞뒤 공백 없음, 제어 문자 없음, `⟦`·`⟧` 없음. 규칙은 익스텐션마다 5개까지.
- **판정 `quietOf(text, rules)`**: 글 끝의 공백(` `·`\t`·`\r`·`\n`)을 지운 뒤 규칙의 `suffix` 로 끝나는지 본다. 규칙은 bridge.yaml 순서대로 보고 첫 것을 쓴다. 봉인 조각이 든 글은 판정하지 않는다. 서버(`server/quiet.go`)와 맥(`agent/trust.mjs`)이 같은 사례표 `server/testdata/quiet-cases.json` 로 시험한다.
- **대상은 Claude 의 답 글(`k: "text"`)뿐이다.** 아래는 대상이 아니다.
  - 사람 말, 결정 카드(권한·질문), 도구, 알림 줄(`notice`·`line`·`local`), btw 답
  - API 가 답 대신 쓴 오류(`model: "<synthetic>"` 인 줄)
- **사람이 직접 동의했을 때만 쓴다.** 그 사람의 동의 기록(`ext-consent.json`)이 지금 해시와 같아야 한다(`quietAgreed`). `extensionConsent: false` 인 서버에서는 규칙을 쓰지 않는다. 그렇지 않으면 운영자가 넣은 규칙이 아무도 읽지 않은 채 모두의 알림을 막는다.

## 3. 서버

- **`convert` (답 글 판정)**: `k == "text"` 이고 synthetic 이 아닌 이벤트마다 판정한다.
  - 줄이 봉인돼 있고 맥이 `"bridgeQuiet":"mac"` 를 붙였으면 → `quiet: "mac"`
  - 그 밖에는 동의한 규칙으로 `quietOf` → `quiet: "<익스텐션 id>"`
  - 평문 줄에 붙은 표지는 믿지 않는다.
- **판정 단위는 턴의 마지막 답이다.**
  - 조용한 답이 오면: `lastQuiet = true`, `quietSeq = seq`, `loudSeq = max(alarmSeq, turnLoud)`. 같은 턴의 앞선 글("확인해 볼게요")도 새 답 점을 띄우지 않는다. 목록 미리보기(`last`)는 바꾸지 않는다.
  - 조용하지 않은 답이 오면: `lastQuiet = false`, `loudSeq = seq`.
  - **경보** 이벤트(`line`, `card`, `notice` 중 `tone: warn`)가 오면: `alarmSeq = loudSeq = seq`, `lastQuiet = false`.
  - 턴이 시작될 때(상태가 busy 가 될 때): `turnSeq = seq`, `turnLoud = loudSeq`.
- **"새 답" 점(페이지)**: `(s.lastQuiet ? s.loudSeq ?? 0 : s.seq) > seen`.
- **`session.done`**: 다음 셋이 모두 맞을 때만 `quiet: true` 를 단다.
  - `lastQuiet` 이다
  - `quietSeq > turnSeq`: 이 턴의 답이다
  - `alarmSeq ≤ turnSeq`: 이 턴에 경보가 없었다

  `quiet` 이 달린 `session.done` 은 **알림 웹훅(`notify`)으로 보내지 않는다.** `bridge.yaml` 훅·익스텐션 훅·페이지 이벤트에는 `quiet` 을 단 채 보낸다. 자동화일 수 있어서 받는 쪽이 고르게 한다. 턴 끝 상태보다 늦게 온 마지막 줄은 그 턴을 시끄럽게 둔다. 알리는 쪽으로 실패한다.
- **Slack**: 조용한 답(`quiet` 있는 `text`)은 스레드에 올리지 않는다(`toCsEvent` 가 `quiet` 을 싣는다). 자동 허용 묶음은 닫는다.
- **바꾸지 않는 것**:
  - 맡긴 세션의 답 이어받기(REQ-F-760 규칙 11): 사람에게 가는 알림이 아니고, 일을 맡긴 세션이 받아야 할 결과다.
  - 웹 푸시·APNs: 원래 답마다 나가지 않는다(결정 카드·관리 알림만). 그래서 바꿀 것이 없다.
  - 탭 제목: 카드·대기만 센다.

## 4. 보안 규칙(사람을 속이지 못하게)

1. **지우지 않고 접는다.** 접힌 답은 타임라인에 `🤫 조용히 접은 답 · <label> · <누가>` 한 줄과 "펼치기"로 남는다. 펼치면 글이 그대로 나온다. 화면 훅의 `hide` 도 같다. 아예 없애는 길은 없다.
2. **접을 수 있는 것은 Claude 의 답 글뿐이다.** 다음은 훅에 오지 않고 규칙 대상도 아니다. 그래서 권한 요청과 경고는 늘 보이고, 카드 푸시도 그대로 나간다.
   - 결정 카드(권한 요청·질문), 오류·경고(`notice`·`line`·synthetic), 사람 말, 도구, 붙잡은 글, btw
3. **경보가 있는 턴은 조용하지 않다(§3).** 프롬프트 주입으로 모델이 표지를 쓰게 만들어도, 같은 턴의 경고·카드를 묻지 못한다.
4. **바꾼 답은 표시한다.** 화면 훅이 글을 바꾸면 답 아래에 `<익스텐션 이름> 이 바꿈` 과 "원문 보기"를 둔다. 누가 바꿨는지(`by`)는 익스텐션 호스트가 붙인다(익스텐션이 정하지 못한다).
5. **규칙이 접은 답은 훅이 펼치지 못한다.** 훅만으로 접은 답은 화면에서만 접히고 알림은 그대로 나간다.
6. **동의**: 동의 글에 "답을 접어요: 끝이 `"[조용히]"` 인 Claude 의 답은 …" 이 보인다. `message.render` 는 쓰는 것 목록에 보인다. 규칙은 extension.yaml 에 있어서 바뀌면 해시가 바뀌고 다시 묻는다. §2 처럼 사람의 명시적 동의가 있어야 한다.
7. **맥과 짝지은 기기**(REQ-S-091)에서는 익스텐션 코드가 뜨지 않는다. 그래서 화면 훅은 거기서 돌지 않는다. 표지에 따른 접기는 페이지 본체가 하므로 거기서도, `?noext=1` 에서도 같다.

## 5. 봉인(1.394)

서버는 봉인된 답의 글을 못 본다. 처음 설계는 서버가 익스텐션 규칙을 맥에 보내고, 맥이 평문 표지를 붙이는 것이었다. 검토에서 이것이 **봉인 우회**임이 드러났다.

- 서버가 아무 끝 글자나 보낸다.
- 맥이 맞으면 평문 `bridgeQuiet` 를 붙인다.
- 서버는 `resync` 로 지난 줄을 다시 받는다.

이렇게 하면 서버가 봉인된 답의 끝을 한 글자씩 맞춰 볼 수 있다. 그래서 바꿨다:

- **봉인하는 맥은 서버가 준 규칙을 받지 않는다.** 그 맥의 터미널에서 사람이 정한 끝 글자만 쓴다: `node ~/.claude-bridge/agent.mjs trust quiet add "[조용히]"`(`rm`, 목록은 인자 없이, 5개까지, agent.json `trustQuiet`, 에이전트가 덮어쓰지 않는다).
- 맥은 봉인하는 줄 중 Claude 답(`type: "assistant"`)의 text 블록이 맞으면 `"bridgeQuiet":"mac"` 를 평문으로 붙인다. 서버에 새는 것은 "이 답이 그 맥 주인이 정한 끝으로 끝났다" 1비트뿐이다. 이는 서버가 알림을 막으려면 알아야 하는 것이다.
- 봉인 중에는 익스텐션 규칙이 쓰이지 않는다. 서버가 글을 못 보기 때문이다.
- 표지를 단 줄을 서버가 꾸며 넣을 수는 있다. 그러면 답이 접힌 한 줄로 보일 뿐 지워지지 않는다(펼치면 짝지은 기기가 푼 글). 서버는 원래 이벤트를 빼먹을 수도 있으니, 새로 생기는 힘이 아니다.

## 6. 페이지

- **접을지**: 이벤트의 `quiet` 이 `"mac"` 이거나, 이 사람이 직접 동의한(`quietAgreed`) 규칙 있는 익스텐션이면 접는다. 동의를 거두면 예전에 접힌 답도 펼쳐 보인다(알림은 이미 지나갔다).
- **`message.render`**: 동기, `around` 만.
  - 인자: `{sid, seq, text, quiet: {ext, name, label} | null, isLast}`
  - 결과: `{text}` 또는 `{hide: true, reason?}`
  - 기본 구현: `quiet` 이면 `{hide: true, reason: label}`, 아니면 `{text}`
  - 익스텐션 호스트가 각 처리기의 결과에 `by`(바꾼 익스텐션 id)를 붙인다. 처리기가 `next` 에 넘긴 글을 바꿨을 때도 붙인다.
- **쓰는 중 글**(`Writing`)은 대상이 아니다. 기록이 오면 접힌다.
- 접힌 마지막 답의 선택지 버튼은 그리지 않는다. 펼치면 그린다.

## 7. 폴링(1.403)·로컬 화면(1.398)

- **폴링**: SSE 와 같은 메시지를 커서로 받는다. `quiet` 은 이벤트의 필드이고, `lastQuiet`·`loudSeq` 는 세션의 필드라 그대로 실린다.
- **로컬 화면**(127.0.0.1): 터미널 화면과 목록만 보여 준다. 답 타임라인·"새 답" 표시·알림이 없어서 대상이 아니다.

## 8. 한계

- **표지는 답의 맨 끝에 쓴다.**
  - 서버는 선택지·할 일 블록을 떼어 낸 글로, 봉인한 맥은 원래 블록 글로 판정한다.
  - `MAX_TEXT`(40,000자)로 잘린 답은 끝 표지가 없어진다.
- **Slack 이 이미 받은 글**: 한 턴의 앞선 중간 글은 올 때 바로 Slack 스레드에 올라간다. 끝에서 조용하다고 판정돼도 되돌리지 않는다.
- **맥의 `agent.json` 훅**(REQ-F-821)의 `session.done` 에는 `quiet` 이 없다.
- **화면 훅만으로 접은 답**은 알림을 막지 못한다(§4 규칙 5).

## 9. 적대적 검토에서 고친 것

| 지적 | 처리 |
|---|---|
| 봉인 우회: 서버가 규칙을 골라 1비트씩 알아냄 | 서버 규칙 전송 없앰, 맥 터미널 규칙만(§5) |
| `extensionConsent: false` 면 동의 없이 적용 | 명시적 동의만(`quietAgreed`) |
| 표지 하나로 같은 턴의 경고까지 묻음 | 경보 이벤트가 있는 턴은 시끄럽게(`alarmSeq`) |
| API 오류도 `text` 로 옴 | synthetic 줄은 판정하지 않음 |
| 턴 끝과 마지막 줄 순서 | 이 턴의 답일 때만(`quietSeq > turnSeq`), 아니면 알림 |
| `toCsEvent` 가 `quiet` 을 빠뜨림·Slack 묶음 | 실음·`endRun` |
| 짝지은 기기에서 규칙 출처를 못 믿음 | 페이지는 표지만 따르고, 접기는 지우지 않음(§4·§5) |
