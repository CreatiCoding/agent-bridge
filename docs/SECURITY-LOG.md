- **고친 것** (SPEC 1.317):
  - 낮음: https 응답에 HSTS 가 없었다 → `Strict-Transport-Security: max-age=31536000`(하위 도메인 제외), REQ-S-082.

## 2026-10-28 (수)

- **본 범위**: 최근 24시간 origin/main 커밋은 앞 회차의 보안 커밋(`6577f9a`) 하나라 그 변경을 다시 봄. 수요일 중점: 에이전트(`agent/*.mjs`) — 위험 호출 판별(`riskyCall`)과 그것을 쓰는 두 곳(PermissionRequest 훅의 `autoAllowAnswer`, 화면 확인 창의 `surfaceDialog`), 세션 안의 sudo(감싸기·askpass·`/askpass`·서버 `sudoask`)와 입력창 `:sudo`, 업데이트 받기(`update`·`manifestSigned`·순번)와 적용(`applyUpdate`), 에이전트 로컬 HTTP 의 키 확인.
- **고친 것** (SPEC 1.338):
  - 중간: 안전한 전부 허용(allowAll 아님)에서 따옴표 안·백틱·경로·`\`를 붙여 쓴 sudo 를 위험 호출로 읽지 못해 묻지 않고 허용했다. 관리자 비밀번호가 열린 5분 안이면 세션의 sudo 감싸기가 askpass 로 비밀번호를 그대로 받아 root 로 돈다 → sudo 앞뒤 경계를 넓힘, REQ-F-759·AC-1465.
  - 낮음: `git push` 의 붙여 쓴 짧은 옵션(`-fu`), `--mirror`, 원격 브랜치 지우기가 강제 push 로 읽히지 않았다 → 함께 묻는다, REQ-F-759·AC-1465.
- **문제 없음으로 본 것**: 업데이트는 파일 이름·길이·SHA-256 목록과 순번에 대한 ed25519 서명이 맞고 순번이 지금 것 이상일 때만 받고, 적용 전에 문법·링크 검사. 에이전트 로컬 HTTP 는 키를 바이트로 상수 시간 비교하고, 훅 키는 훅·askpass 경로에만 통함. `:sudo` 와 askpass 는 매번 서버에 묻고 서버는 세션 주인·Slack 여부를 봄. sudo 감싸기·askpass 는 값을 셸 따옴표로 감싸 씀.
- **보류**:
  - 화면 확인 창을 눌러 주는 쪽은 훅이 남긴 표시(최근 위험 호출)와 마지막 도구로 판단한다. 훅이 닿지 않았거나 권한 요청이 겹쳐 올 때 이 판단이 어긋날 수 있는지는 Claude Code 가 그런 순서로 부르는지 확인하지 못해 관찰만 한다.
  - `git clean -f`·`git checkout -- .`·`find … -delete` 같은 작업 버리기·삭제는 REQ-F-759 의 목록에 없다(새 범주라 정책 결정이 필요).

- **고친 것** (SPEC 1.340):
  - 낮음: SSE 스트림은 받는 쪽이 읽지 않으면 보낼 것이 서버 메모리에 끝없이 쌓였다(로그인한 사용자, 데모 계정 포함. 쓰기 기한이 없어 막힌 연결도 풀리지 않음) → 기다리는 양이 64 MiB 를 넘게 되면 끊고 쓰기 기한으로 막힌 쓰기를 푼다, REQ-S-087.
  - 낮음: 한 사람이 여는 조작 페이지 스트림 수에 한도가 없어, 상태를 보낼 때마다 스트림마다 계산·적재가 늘었다 → 32 개, 넘으면 가장 오래된 것을 닫음, REQ-S-087.
- **문제 없음으로 본 것**: 연동 경로(`/api/bridge/stream`·`up`·`bye`·`upload`·`transcript`)는 호스트 주인과 `conn` 을 확인. 세션을 바꾸는 에이전트 메시지(`lines`·`status`·`card`·`note`·`preview`·`conv`·`stats`·`folder`·`delivered`·`closed`)는 `owns`(같은 계정이고 그 호스트에서 돌거나 옮겨 가는 중)를 확인. `toast`·`screen`·`error` 는 확인이 없지만 보내는 사람 자신의 조작 페이지에만 간다. 명령의 답과 `got` 은 명령을 보낸 호스트에서 온 것만 받는다. 미리보기 웹소켓 메시지는 그 소켓의 호스트에서 온 것만. 미리보기 밖의 웹소켓 업그레이드는 바로 닫는다. hello 의 세션 목록은 남의 세션 id 를 건너뜀. 데모 계정은 연동 경로를 쓸 수 없다.
- **보류**:
  - 연동 탭이 올리는 `health`·`hello`·`logs` 의 일부 칸은 길이를 자르지 않고 기기 기록·상태에 남는다. 본문 한도(32 MB) 안이고 같은 계정의 맥이 보내는 것이라 관찰만 한다.

  - 낮음: 운영 탭의 붙여 넣고 검사도 같은 이스케이프로 지나가, 관리자가 이 서버의 다른 환경변수 값을 오류 문구로 볼 수 있었다 → 같은 방식으로 막음, REQ-S-088.
- **문제 없음으로 본 것**: 데모 허용 목록은 경로 모양·방법을 하나씩 맞추고 본문의 호스트·세션 id 를 자기 것인지 보며, `do`·`:` 명령이 부르는 내부 동작은 데모 맥으로만 가고 데모 맥은 모르는 명령을 거절한다(가벼운 복제로 세션 수 한도를 넘지 못함). 세션 경로는 모두 `ownSession`(주인만), 세션 만들기·옮기기는 `ownHost`. 전부 허용을 켜는 길은 모두 `modeOk` 를 거치고, 맥이 알려 온 상태도 꺼진 모드면 끈다. 위임은 자기 호스트에만, 맡긴 세션은 같은 계정만. Slack 버튼은 연결된 본인만 받는다. 에이전트 권한 훅은 세션 id 로 그 맥의 그 세션 정책만 쓴다. 헤더 로그인은 비밀 헤더를 상수 시간 비교하고 TCP 피어가 trustFrom 안일 때만(무중단 교체 때는 서명한 피어). 설정 API 는 관리자만. 익스텐션의 사람별 저장·비밀값·동의는 uid 로 나뉘고, `/ext/` 는 로그인·해시·동의를 모두 본다. 훅 명령은 셸 없이 절대 경로, 웹훅·훅 주소는 운영자 설정만 정한다. 데모 계정은 익스텐션을 받지 않는다.
