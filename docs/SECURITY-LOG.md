# 보안 점검 기록

매일 도는 보안 점검이 본 범위와 찾은 것을 날짜순으로 쌓는다. 고친 것은 커밋을, 보류한 것은 이유만 짧게 적는다(공개 저장소라 고치지 않은 것의 재현 방법은 적지 않는다).

## 2026-10-25 (일, 첫 회차)

- **본 범위**: 최근 7일 origin/main 커밋(`fe5168e`~`2d8b7d0`, 32개): Go 서버 재작성(`d6f3c1e`)의 소유자·잠금·데모·경로·본문 한도 확인을 Node 판과 대조, 권한 알림의 허용·거부(`5f6571e`), 화면 없는 기기 로그인(`a76e7dc`), 전부 허용 분리(`7e60dad`), zeropty 내려받기 해시 확인. 일요일 중점: 의존성(ui·website `yarn npm audit`, Go·node·alpine 이미지 판), Dockerfile, CSP, 보안 헤더(운영 응답 실측).
- **고친 것** (SPEC 1.317):
  - 낮음: https 응답에 HSTS 가 없었다 → `Strict-Transport-Security: max-age=31536000`(하위 도메인 제외), REQ-S-082.
  - 낮음(강화): 페이지 CSP 에 `base-uri 'self'`·`object-src 'none'`, REQ-S-011.
  - 낮음: 데모 계정의 `:sudo` 글 막기가 Go 의 ASCII 전용 `\s` 때문에 유니코드 공백으로 지나갔다(데모 맥은 sudo 를 처리하지 않아 실행 없음) → JS 공백 규칙 `re()`, REQ-S-068.
- **문제 없음으로 본 것**: ui 의존성 감사 결과 없음. Go 1.27.3·node 22.23.4·alpine 3.22 최신 패치. 컨테이너는 root 로 뜨지만 서버가 시작할 때 node 사용자로 내려간다(dropRoot). Go 판의 소유자·잠금·에이전트 메시지 확인은 Node 판과 같음.
- **보류**:
  - website(문서 사이트)의 mermaid 11.4.1·vite 5 경고: 다이어그램은 저장소가 쓴 내용뿐이고 vite·esbuild 는 빌드 때만 돈다. 다음 의존성 갱신 때 함께 올린다.
  - Dockerfile 에 `USER` 없음: 위 dropRoot 로 갈음. 이미지에서 바꾸려면 운영 볼륨 소유권을 바꿔야 해서 하지 않았다.
  - 연동 경로의 한 비교가 Node 판과 조금 다르게 동작한다: 닿는 경로를 찾지 못했고 같은 계정 안의 일이라 관찰만 한다.

## 2026-10-26 (월)

- **본 범위**: 최근 24시간 origin/main 커밋(`28f1e8a`~`912126b`, 21개): 서비스 API(`f0facd7`), 연동 키 하루 교체·교체 기록(`e21986d`·`417e10f`), 헤드리스 Chrome 키(`28f1e8a`·`c7fa6e7`), 디스크 관리·머지된 worktree 정리·디스크 정리 도움(`d99953c`·`5e6951b`·`77abe6f`·`6336778`), 기기 사용률·배터리(`892d3e5`·`fee4d4c`·`6b27dad`). 월요일 중점: 인증·쿠키·세션(GitHub·Apple·QR·데모 로그인, `__Host-` 쿠키 속성, 로그아웃·계정 삭제의 로그인 폐기, 출처 검사, safeNext).
- **고친 것** (SPEC 1.336):
  - 낮음: 서비스 API 가 `BRIDGE_SERVICE_UID` 계정이 허용 목록에서 빠지거나 없어져도 그 사람의 맥에 세션을 열 수 있었다 → 계정이 살아 있을 때만, REQ-S-085.
  - 낮음: 디스크 정리 도움의 허용이 누구에게 주는지 싣지 않아, 주인이 본 운영자와 다른 운영자에게 갈 수 있었다(운영자가 둘 이상일 때) → grant 에 login, REQ-F-804.
  - 낮음: 디스크 관리 폴더 보기가 홈 안의 링크를 따라 홈 밖 폴더 이름·크기를 보였다(허용받은 운영자에게도) → 링크를 푼 실제 경로로 검사, REQ-F-804.
- **문제 없음으로 본 것**: 서비스 토큰은 32자 이상·SHA-256 상수 시간 비교, 쿠키·출처 검사와 분리. 키 교체 기록·배터리는 서버가 알려진 칸만 골라 넘김. 화면 없는 기기용 QR 코드는 HeadlessChrome 이 아닌 브라우저에서 로그인되지 않음. 로그인 쿠키는 `__Host-`·HttpOnly·SameSite=Lax·Secure, 허용 목록은 요청마다 다시 봄.
- **보류**: 없음(지난 회차 보류 항목은 그대로).

## 2026-10-27 (화)

- **본 범위**: 최근 24시간 origin/main 커밋은 앞 회차의 보안 커밋(`86a4231`) 하나라 그 변경을 다시 봄. 화요일 중점: API 입력 검증·경로 순회·크기 한도 — 서버의 요청 본문 한도(`body`/`readAll` 쓰는 곳 전부), 경로 정규식과 파일 경로 만드는 곳(그림·영상·제보·업로드 id), 미리보기 HTTP·웹소켓, 영상 올리기, 에이전트가 경로를 받는 명령(`readimage`·`readfile`·`dirs`·`send`·`putimg`·`img`·`http`).
- **고친 것** (SPEC 1.337):
  - 낮음: 미리보기 웹소켓이 프레임 하나만 16 MB 로 막고 조각을 합친 크기는 보지 않아, 서버가 메시지를 메모리에 끝없이 모을 수 있었다(미리보기 토큰을 가진 로그인 사용자) → 합친 크기로 막고 1009, REQ-S-086.
  - 낮음: 영상 올리기가 하나 500 MB 만 막고 사람마다 총량이 없어, 허용된 사용자가 서버 디스크를 채울 수 있었다 → 한 사람 2 GiB(올린 영상·올리는 중·제보 영상 합), REQ-S-086.
- **문제 없음으로 본 것**: JSON 본문은 경로마다 한도가 있고 넘으면 413. 그림·영상·제보 id 는 정규식(40 hex·확장자)으로만 파일 경로가 되고, 제보 그림은 서버가 해시로 이름을 붙임. 에이전트의 그림 읽기는 링크를 푼 실제 경로로 세션 폴더·임시 폴더 안만, 파일 앞머리로 그림인지 확인. 연동 탭이 넘긴 영상 경로도 링크를 푼 경로로 그림 폴더 안만.
- **보류**: 없음(지난 회차 보류 항목은 그대로).

## 2026-10-28 (수)

- **본 범위**: 최근 24시간 origin/main 커밋은 앞 회차의 보안 커밋(`6577f9a`) 하나라 그 변경을 다시 봄. 수요일 중점: 에이전트(`agent/*.mjs`) — 위험 호출 판별(`riskyCall`)과 그것을 쓰는 두 곳(PermissionRequest 훅의 `autoAllowAnswer`, 화면 확인 창의 `surfaceDialog`), 세션 안의 sudo(감싸기·askpass·`/askpass`·서버 `sudoask`)와 입력창 `:sudo`, 업데이트 받기(`update`·`manifestSigned`·순번)와 적용(`applyUpdate`), 에이전트 로컬 HTTP 의 키 확인.
- **고친 것** (SPEC 1.338):
  - 중간: 안전한 전부 허용(allowAll 아님)에서 따옴표 안·백틱·경로·`\`를 붙여 쓴 sudo 를 위험 호출로 읽지 못해 묻지 않고 허용했다. 관리자 비밀번호가 열린 5분 안이면 세션의 sudo 감싸기가 askpass 로 비밀번호를 그대로 받아 root 로 돈다 → sudo 앞뒤 경계를 넓힘, REQ-F-759·AC-1465.
  - 낮음: `git push` 의 붙여 쓴 짧은 옵션(`-fu`), `--mirror`, 원격 브랜치 지우기가 강제 push 로 읽히지 않았다 → 함께 묻는다, REQ-F-759·AC-1465.
- **문제 없음으로 본 것**: 업데이트는 파일 이름·길이·SHA-256 목록과 순번에 대한 ed25519 서명이 맞고 순번이 지금 것 이상일 때만 받고, 적용 전에 문법·링크 검사. 에이전트 로컬 HTTP 는 키를 바이트로 상수 시간 비교하고, 훅 키는 훅·askpass 경로에만 통함. `:sudo` 와 askpass 는 매번 서버에 묻고 서버는 세션 주인·Slack 여부를 봄. sudo 감싸기·askpass 는 값을 셸 따옴표로 감싸 씀.
- **보류**:
  - 화면 확인 창을 눌러 주는 쪽은 훅이 남긴 표시(최근 위험 호출)와 마지막 도구로 판단한다. 훅이 닿지 않았거나 권한 요청이 겹쳐 올 때 이 판단이 어긋날 수 있는지는 Claude Code 가 그런 순서로 부르는지 확인하지 못해 관찰만 한다.
  - `git clean -f`·`git checkout -- .`·`find … -delete` 같은 작업 버리기·삭제는 REQ-F-759 의 목록에 없다(새 범주라 정책 결정이 필요).
