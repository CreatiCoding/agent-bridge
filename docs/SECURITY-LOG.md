# 보안 점검 기록

매일 도는 보안 점검이 본 범위와 찾은 것을 날짜순으로 쌓는다. 고친 것은 커밋을, 보류한 것은 이유만 짧게 적는다(공개 저장소라 고치지 않은 것의 재현 방법은 적지 않는다).

## 2026-10-25 (일, 첫 회차)

- **본 범위**: 최근 7일 origin/main 커밋(`fe5168e`~`2d8b7d0`, 32개): Go 서버 재작성(`d6f3c1e`)의 소유자·잠금·데모·경로·본문 한도 확인을 Node 판과 대조, 권한 알림의 허용·거부(`5f6571e`), 화면 없는 기기 로그인(`a76e7dc`), 전부 허용 분리(`7e60dad`), zeropty 내려받기 해시 확인. 일요일 중점: 의존성(ui·website `yarn npm audit`, Go·node·alpine 이미지 판), Dockerfile, CSP, 보안 헤더(운영 응답 실측).
- **고친 것** (SPEC 1.317):
  - 낮음: https 응답에 HSTS 가 없었다 → `Strict-Transport-Security: max-age=31536000`(하위 도메인 제외), REQ-S-082.
  - 낮음(강화): 페이지 CSP 에 `base-uri 'self'`·`object-src 'none'`, REQ-S-011.
  - 낮음: 데모 계정의 `:sudo` 글 막기가 Go 의 ASCII 전용 `\s` 때문에 유니코드 공백으로 지나갔다(데모 맥은 sudo 를 처리하지 않아 실행 없음) → JS 공백 규칙 `re()`, REQ-S-068.
- **문제 없음으로 본 것**: ui 의존성 감사 결과 없음. Go 1.27.3·node 22.23.4·alpine 3.22 최신 패치. 컨테이너는 root 로 뜨지만 서버가 시작할 때 node 사용자로 내려간다(dropRoot). Go 판의 소유자·잠금·에이전트 메시지 확인은 Node 판과 같음.
- **보류**:
  - website(문서 사이트)의 mermaid 11.4.1·vite 5 경고: 다이어그램은 저장소가 쓴 내용뿐이고 vite·esbuild 는 빌드 때만 돈다. 다음 의존성 갱신 때 함께 올린다.
  - Dockerfile 에 `USER` 없음: 위 dropRoot 로 갈음. 이미지에서 바꾸려면 운영 볼륨 소유권을 바꿔야 해서 하지 않았다.
  - 연동 경로의 한 비교가 Node 판과 조금 다르게 동작한다: 닿는 경로를 찾지 못했고 같은 계정 안의 일이라 관찰만 한다.
