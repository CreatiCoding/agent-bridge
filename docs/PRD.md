## 1. 한 줄 정의

claude-bridge 는 맥에서 도는 진짜 Claude Code 세션을, 그 맥의 브라우저에 켜 둔 연동 페이지를 통해 웹 사이트에 연결하는 웹 사이트다. 연결된 세션으로 두 가지를 한다.

1. **옮기기**: 맥북의 세션을 아이맥으로(또는 반대로) 옮겨, 옮겨 간 맥에서 이어서 작업한다.
2. **조작하기**: 핸드폰에서 웹 사이트에 접속해 맥북 세션이든 아이맥 세션이든 그 Claude 와 대화하고 작업한다.

둘은 서로 별개의 기능이다.

예전 Slack 기반 도구와의 차이는 하나다. 그 도구는 세션을 Slack 스레드에 잇고, claude-bridge 는 세션을 웹 사이트에 잇는다. Slack 은 핵심이 아니라 사용자별 플러그인으로만 붙는다.

## 2. 핵심 원칙 (우선순위 순, 타협 불가)

원칙끼리 부딪히면 번호가 작은 쪽이 이긴다.

### P1. 세션은 맥에 있다 [요구]

Claude 세션은 아이맥·맥북에서 도는 로컬 세션이다. 그 맥은 에이전트로서 Web 과 연결된다. 웹 서버는 세션을 실행하지 않는다.

- 코드, 파일, 자격 증명은 사용자의 맥에 남는다. 세션의 사본은 서버 디스크에도 있다(P4). 사본은 이어 가기 위한 것이고, 실행은 언제나 맥에서 한다.
- 세션은 한 시점에 한 맥에서만 돈다. 어느 맥에서 도는지는 언제나 사용자가 정한다(P3, P4).
- 웹 서버는 세션을 대신 돌리지 않는다. 연결 가능한 맥이 하나도 없으면 세션은 멈춰 있고, 그 사실을 알린다(P4).

### P2. 맥과 Web 을 잇는 것은 연동 페이지의 브라우저 JavaScript 다 [요구]

아이맥·맥북은 브라우저에 **이 사이트의 페이지**를 켜 두고, 그 페이지의 JavaScript 를 통해서 Web 과 연동한다. 연동 전용 페이지가 따로 떠 있을 필요는 없다: 조작 화면이 떠 있으면 그 화면이 뒤에서 연동한다(0.8, 요청자 결정).

- 맥의 로컬 프로세스는 웹 서버에 직접 접속하지 않는다. 바깥으로 나가는 연결은 연동 페이지만 만든다.
- 사이트의 탭을 모두 닫으면 그 맥은 Web 에서 끊긴다. 다시 열면 붙는다.
- 따라서 맥에 포트를 열거나, 터널·VPN·고정 IP 를 둘 필요가 없다.
- 예외(0.9, 요청자 결정): 사용자가 호스트마다 "헤드리스 연동 모드" 를 켜면, 에이전트가 그 맥의 Chrome 을 화면 없이 띄워 연동 페이지를 맡긴다. 잇는 것은 여전히 브라우저의 JavaScript 이지만, 그 브라우저를 에이전트가 띄우므로 그 호스트에서는 "에이전트는 혼자서는 바깥과 연결하지 않는다" 가 성립하지 않는다. 기본은 꺼짐이다.

### P3. 세션은 맥 사이를 옮겨 다닌다 [요구]

"세션을 주고 받는다" 는 맥북의 세션을 아이맥으로 옮겨서 작업한다는 뜻이다. 방향은 어느 쪽이든 된다.

- 옮긴 뒤에는 받은 맥에서 같은 대화가 이어진다. 처음부터 다시 설명하지 않는다.
- 옮긴 세션은 보낸 맥에서 더 돌지 않는다. 같은 대화가 두 맥에서 동시에 돌지 않는다.
- 옮기기가 실패하면 세션은 보낸 맥에 그대로 남는다. 중간에 사라지지 않는다.

### P4. 서버가 세션을 싱크하고, 끊기면 전환할지 묻는다 [요구]

- 서버는 세션을 주기적으로 디스크에 싱크한다.
- 세션의 연결이 끊어진 상태라면, 마지막으로 연결되었던 기기와 연결을 시도한다.
- 기기를 자동으로 전환하지 않는다. 연결이 끊어졌을 때 다른 기기로 전환할지를 사용자에게 묻고, 사용자가 고르면 전환한다.
- 연결 가능한 에이전트가 하나도 없다면 사용자에게 알려 준다.
- 전환한 뒤 원래 기기가 돌아와도 자동으로 돌아가지 않는다. 사용자가 돌아가겠다고 하면, 돌아온 기기에 남아 있던 데이터 대신 최신 데이터로 그 기기를 덮어쓴 뒤 세션을 옮긴다. 최신은 언제나 지금 세션이 돌고 있는 쪽이다.
- 작업 폴더 전체를 싱크하지 않는다. 싱크하는 것은 다음뿐이다.
  - 작업 폴더가 git 저장소가 아닐 때: `SESSION.md`, `AGENTS.md`, `CLAUDE.md` 같은 지침·인수인계 파일.
  - 작업 폴더 자체가, 또는 바로 1단계 하위 폴더가 git 저장소일 때: 그 저장소의 브랜치와 커밋 sha. 받은 기기에서 그 브랜치·커밋을 불러올 수 있어야 한다.
  - 브랜치와 sha 를 싱크할 때, 그 브랜치가 기본 브랜치(`main`·`develop`·`master`)가 아니면 자동으로 push 해 둔다. 세션마다 다르게 설정할 수 있고, 기본값은 "싱크할 때 자동으로 push 된다" 이다.

그래서 세션은 특정 맥이 꺼져 있어도 사라지지 않고, 사용자가 고른 맥에서 이어진다. 맥북에서 보내 두고 나중에 아이맥에서 받는 것도 이 원칙으로 된다.

### P5. 핸드폰은 Web 으로 조작한다 [요구]

P3 과 별개로, 핸드폰은 앱 설치 없이 웹 사이트에서 연동된 맥북 세션이나 아이맥 세션의 Claude 와 대화하고 작업한다.

- 조작 화면은 폰 폭(390 px)을 기준으로 먼저 만든다.
- 조작할 수 있는 범위는 터미널에서 할 수 있는 것과 같아야 한다(§4.2).
- 세션이 어느 맥에 있든, 옮겨 간 뒤에도, 폰에서는 같은 세션으로 이어서 보인다.

### P6. 오픈소스다 [요구]

누구나 자기 서버에 올려 자기 맥을 연결할 수 있어야 한다.

- 비밀 값·개인 주소·개인 도메인을 코드에 넣지 않는다. 전부 설정으로 받는다.
- 특정 호스팅에 묶이지 않는다.

### P7. 예전 Slack 기반 도구와 같은 방식으로 세션을 다룬다 [요구]

세션을 붙이고, 읽고, 조작하는 방식은 그 도구를 따른다. 이미 검증된 동작을 다시 발명하지 않는다.

## 3. 구성요소

```
[핸드폰·다른 기기]                       [아이맥 / 맥북]
 조작 페이지  ⇄  웹 서버  ⇄  연동 페이지(브라우저 JS)  ⇄  로컬 에이전트  ⇄  Claude Code 세션
              (인터넷)                    (같은 맥 안, 127.0.0.1)          (tmux)
```

| # | 구성요소      | 어디서 도는가        | 하는 일                                                                  | 근거 |
|---|---------------|----------------------|--------------------------------------------------------------------------|------|
| 1 | 로컬 에이전트 | 맥 (Node 프로세스)   | Claude Code 세션을 띄우고, 출력을 읽고, 입력·키를 넣는다. `127.0.0.1` 에서만 듣는다 | P1, P7 |
| 2 | 연동 페이지   | 맥의 브라우저 탭     | 로컬 에이전트와 웹 서버 양쪽에 연결해 메시지를 그대로 옮긴다             | P2 |
| 3 | 웹 서버       | 인터넷 (셀프호스팅)  | 로그인, 기기 등록, 중계, 세션 싱크 보관, 끊긴 세션의 재연결과 전환 묻기   | P3, P4, P5, P6 |
| 4 | 조작 페이지   | 핸드폰·아무 브라우저 | 기기와 세션 목록, 대화, 결정 카드, 입력, 세션 옮기기                     | P3, P5 |

로컬 에이전트가 필요한 이유: 브라우저 JavaScript 는 맥의 프로세스·터미널·파일에 닿을 수 없다. 연동 페이지가 붙을 상대가 맥 안에 있어야 한다. 이 프로세스는 P2 에 따라 바깥으로 연결하지 않고, 같은 맥의 연동 페이지만 받는다.

용어: 아이맥·맥북처럼 로컬 에이전트가 도는 기계를 **호스트**, 조작 페이지를 연 기기를 **조작 기기**라 부른다. 맥북은 호스트이면서 아이맥 세션의 조작 기기일 수 있다.

## 5. 스펙 [제안]

### 5.1 연결

| 구간                        | 방식                                   | 비고 |
|-----------------------------|----------------------------------------|------|
| 연동 페이지 ⇄ 로컬 에이전트 | WebSocket `ws://127.0.0.1:<포트>`      | 루프백만. 포트 기본값은 설정으로 |
| 연동 페이지 ⇄ 웹 서버       | WebSocket `wss://<사이트>/bridge`      | 연동 페이지가 건다 (P2) |
| 조작 페이지 ⇄ 웹 서버       | SSE(받기) + JSON POST(보내기)          | 예전 도구의 웹 앱과 같은 방식 |

- 연동 페이지는 메시지를 해석하지 않고 옮긴다. 양쪽 프로토콜은 같은 메시지 형식(JSON, 한 줄에 하나)을 쓴다.
- 이벤트에는 세션마다 일련번호(`seq`)를 붙인다. 다시 붙을 때 `after=seq` 로 빠진 것만 받는다 (F-16).

### 5.2 로컬 에이전트

- 예전 도구의 브로커에서 Slack 부분을 뺀 것이다: 채널 심(MCP), 훅 전달기, 트랜스크립트 읽기, tmux 키 입력·화면 캡처, 세션 레지스트리, 이벤트 로그.
- `127.0.0.1` 에만 바인드한다. 다른 주소로는 뜨지 않는다.
- WebSocket 연결은 두 조건을 모두 만족할 때만 받는다: `Origin` 이 설정된 사이트 주소와 같다, 그리고 등록 때 받은 호스트 비밀 값을 제시한다. 로컬의 다른 웹 페이지가 붙는 것을 막기 위해서다.
- 상태는 맥의 `~/.claude-bridge/` 에 둔다 (이벤트 로그, 살아 있는 세션, 설정).

### 5.3 웹 서버

- 세션의 사본을 디스크에 둔다(P4). 사본은 대화(트랜스크립트), 이벤트 로그, 세션 정보(폴더·모델·마지막 호스트·마지막 싱크 시각)다.
- 싱크는 호스트 → 서버 방향이다. 로컬 에이전트가 지난 싱크 뒤에 늘어난 부분만 연동 페이지를 거쳐 보내고, 서버가 파일에 덧붙인다. 주기는 설정값이고, 턴이 끝날 때도 한 번 보낸다(기본 주기는 Q1c).
- 그 밖에 저장하는 것: 사용자, 등록된 호스트(이름·비밀 값의 해시·마지막 연결 시각), 로그인 세션.
- 조작 페이지는 호스트가 끊겨 있어도 서버의 사본으로 대화를 읽는다.

#### 끊겼을 때의 순서 (F-51~F-56)

1. 세션의 호스트가 끊긴 것을 서버가 안다(연동 페이지의 WebSocket 이 닫힘).
2. 서버는 마지막으로 연결되었던 호스트가 다시 붙기를 기다린다. 붙으면 그 호스트의 세션이 그대로 이어지고, 끊긴 동안의 것을 싱크한다. 사람에게 묻지 않는다.
3. 끊겨 있는 동안 조작 페이지는 그 세션에 "연결 끊김" 과 함께 전환할지를 묻는다. 선택지는 연결된 다른 호스트들과 "기다리기" 다. 서버가 스스로 고르지 않는다.
4. 사용자가 호스트를 고르면, 그 호스트의 로컬 에이전트가 서버의 사본을 받아 `claude --resume` 으로 연다. §5.4 의 옮기기와 같은 절차이고, 보내는 쪽이 서버인 것만 다르다.
5. 연결된 호스트가 하나도 없으면 "연결 가능한 에이전트 없음" 으로 표시하고 알린다. 호스트가 붙으면 3번의 선택지에 나타난다.

#### 전환한 뒤 원래 호스트가 돌아왔을 때 (F-55, F-56)

- 돌아온 호스트의 세션은 다시 돌리지 않는다. 그 세션은 이미 다른 호스트에서 돌고 있다(P3). 로컬 에이전트는 붙을 때 서버에 세션의 현재 호스트를 묻고, 자기가 아니면 그 세션을 열지 않는다.
- 조작 페이지는 "원래 호스트가 돌아왔음" 을 보여 주고 돌아갈지를 고르게 한다.
- 돌아가기를 고르면: 지금 호스트에서 마지막 싱크를 한 번 더 한다 → 돌아온 호스트에 남아 있던 그 세션의 데이터(트랜스크립트·이벤트 로그·싱크 대상 파일)를 서버의 최신 사본으로 덮어쓴다 → 돌아온 호스트에서 연다 → 열린 것을 확인한 뒤 지금 호스트의 세션을 끝낸다.
- 덮어쓰면 돌아온 호스트에만 있던, 끊기기 직전의 싱크되지 않은 대화는 사라진다. 덮어쓰기 전에 그 호스트의 `~/.claude-bridge/overwritten/` 에 사본을 남긴다 [제안, Q1e].

### 5.4 세션 옮기기

옮기는 것은 두 가지다: **대화**(Claude Code 의 트랜스크립트)와 **작업 폴더의 상태**.

- 대화: 보낸 호스트의 로컬 에이전트가 트랜스크립트(`~/.claude/projects/<폴더>/<session_id>.jsonl`)를 내보내고, 받은 호스트의 로컬 에이전트가 자기 작업 폴더에 맞는 자리에 써 넣은 뒤 `claude --resume <session_id>` 로 연다. 두 맥의 폴더 경로가 달라도(사용자 이름·위치) 되어야 한다.
- 경로: P2 에 따라 맥끼리 직접 연결하지 않는다. 보낸 맥의 연동 페이지 → 웹 서버 → 받은 맥의 연동 페이지로 흐른다. 받는 맥이 연결돼 있지 않으면 서버의 사본에서 나중에 받는다(§5.3).
- 순서: ① 받는 쪽 확인(F-42) → ② 보낸 쪽 세션을 쉬는 상태에서 잠금 → ③ 전송과 무결성 확인(크기·해시) → ④ 받은 쪽에서 열기 → ⑤ 열린 것을 확인한 뒤에야 보낸 쪽 세션 종료. ④ 까지 어디서든 실패하면 잠금을 풀고 보낸 쪽이 그대로 이어 간다(F-43).
- 세션은 옮겨도 같은 식별자를 유지한다. 조작 페이지는 식별자로 세션을 따라간다(F-46).
- 작업 폴더는 통째로 옮기지 않는다. 무엇을 옮기는지는 §5.5 가 정한다.
- 확인 필요: 다른 맥에서 가져온 트랜스크립트로 `--resume` 이 그대로 되는지, 트랜스크립트 안의 절대 경로가 달라질 때 어떻게 되는지. §8 의 1단계에서 실험한다.

### 5.5 작업 폴더 싱크

작업 폴더 전체는 싱크하지 않는다(P4). 로컬 에이전트는 싱크할 때마다 작업 폴더를 다음처럼 본다.

| 대상 | 조건 | 싱크하는 것 | 받은 호스트에서 |
|------|------|-------------|-----------------|
| 작업 폴더 자체 | git 저장소가 아니다 | `SESSION.md`, `AGENTS.md`, `CLAUDE.md` 의 내용 | 같은 이름으로 작업 폴더에 써 넣는다 |
| 작업 폴더 자체 | git 저장소다 | 브랜치, 커밋 sha | 그 브랜치·커밋을 불러온다 |
| 1단계 하위 폴더 | git 저장소다 | 폴더 이름, 브랜치, 커밋 sha | 폴더마다 그 브랜치·커밋을 불러온다 |

- 2단계 이하의 하위 폴더는 보지 않는다.
- 작업 폴더가 git 저장소가 아니면서 1단계 하위에 git 저장소가 있으면, 첫째 줄과 셋째 줄을 함께 적용한다.
- git 저장소에서는 지침 파일을 따로 싱크하지 않는다. 커밋에 들어 있는 것으로 본다.
- [제안] 브랜치·sha 와 함께 원격 주소(`origin` URL)도 싱크한다. 받은 호스트에 그 저장소가 없을 때 무엇을 받아 와야 하는지 알기 위해서다.
- [제안] "불러온다" 는 `git fetch` 뒤 그 브랜치를 체크아웃하고 싱크된 sha 인지 확인하는 것이다. 받은 호스트의 저장소에 커밋되지 않은 변경이 있으면 건드리지 않고 사람에게 알린다.

#### 자동 push (F-61)

싱크할 때 저장소마다 다음을 한다. 목적은 싱크한 sha 를 받은 호스트가 실제로 불러올 수 있게 하는 것이다.

- 조건: 세션의 자동 push 설정이 켜져 있고(기본 켜짐), 지금 브랜치가 기본 브랜치(`main`·`develop`·`master`)가 아니며, 원격에 없는 커밋이 있다. 지난 싱크 뒤로 sha 가 바뀌지 않았으면 아무것도 하지 않는다.
- 기본 브랜치에서는 push 하지 않는다. 푸시 안 된 커밋이 있으면 알리기만 한다.
- [제안] 강제 push 는 하지 않는다. 원격이 앞서 있거나 갈라져서 거절되면 그대로 두고 알린다.
- [제안] 원격에 그 브랜치가 없으면 같은 이름으로 `origin` 에 만든다.
- [제안] 브랜치가 없는 상태(detached HEAD)에서는 push 하지 않고 sha 만 싱크한다.
- [제안] push 가 실패해도(인증, 네트워크, 훅 거절) 싱크 자체는 계속하고, 그 저장소를 "푸시 안 됨" 으로 표시한다.
- [제안] 기본 브랜치 이름 목록은 설정으로 바꿀 수 있다.
- 설정은 세션마다 둔다. 새 세션은 기본값(켜짐)으로 시작한다.

싱크되지 않는 것: 커밋되지 않은 변경. 자동 push 는 커밋된 것만 보낸다. 옮기기·전환을 시작할 때 커밋되지 않은 변경이나 "푸시 안 됨" 인 저장소가 있으면 미리 알린다(F-42, Q1f).

### 5.6 보안

이 시스템은 인터넷에서 온 요청으로 맥에서 명령이 실행되게 한다. 그래서 다음은 M0 에 포함한다.

- 조작 요청과 옮기기는 로그인한 사용자의 것이고, 그 사용자가 등록한 호스트 사이에서만 일어난다.
- 변경 요청은 같은 출처 + `application/json` 만 받는다 (CSRF).
- 틀린 로그인·토큰 시도는 발신 주소별로 횟수를 제한한다.
- 비밀 값은 주소(URL)에 싣지 않는다.

### 5.7 기술 스택

예전 도구와 같게 간다: Node.js ≥ 22.18 로 TypeScript 를 빌드 없이 실행, 테스트는 `node --test`, 화면 확인은 Playwright. 서버와 에이전트는 의존성 없이 node 내장 모듈만 쓴다.

조작 페이지는 React 로 쓰고 Vite 로 빌드한다(0.9). 공개 npm 패키지만 쓰고, 빌드한 파일을 서버가 내준다. 연동 페이지와 그 밖의 페이지는 프레임워크 없는 JavaScript 그대로다.

저장소 구조:

```
agent/   로컬 에이전트 (맥)
server/  웹 서버
web/     연동 페이지와 그 밖의 페이지
ui/      조작 페이지 (React + Vite)
docs/
```

## 8. 진행 순서 [제안]

1. **실험 두 가지**
   - 연결: 로컬 에이전트(에코) + 연동 페이지 + 웹 서버 + 조작 페이지로 글 한 줄이 폰에서 맥까지 왕복한다. Q5·Q6 을 여기서 확인한다.
   - 옮기기: 맥북의 트랜스크립트를 손으로 아이맥에 옮겨 `--resume` 이 이어지는지 본다(§5.4 의 확인 필요).
2. **M0 조작**: 로그인, 호스트 등록, 세션 목록, 대화 보기, 글 보내기, 권한 응답, 중단, 새 세션.
3. **M0 싱크와 전환**: F-50~F-58, F-61.
4. **M0 옮기기**: F-40~F-44.
5. **M1**: 질문·플랜 카드, 첨부, 화면 보기, QR 로그인, 턴 중 옮기기, 옮긴 세션 따라가기.
6. **공개**: 설치 문서, 라이선스, 리포지토리 공개 전환.
